# 최종 검토: 질문 방식(Grill)과 지침·스킬 설정 요청

## 결론

- **치명적인 문제는 없습니다.** 배포를 막을 사유는 없습니다.
- 다만 중간 1·2는 프롬프트 문구 몇 줄만 고치면 됩니다. 함께 고쳐서 배포하기를 권장합니다. 그대로 배포해도 데이터가 손실되거나 개인정보가 새지는 않습니다.
- 확인 범위: 전달받은 diff·함수·프롬프트만 읽었습니다. 아무것도 실행하지 않았고, `handoffSteps`, `workflowText`, `outputSummary`, `hydrateMaterial`, `syncRules`의 본문은 보지 못했습니다.

## 1차 검토 지적의 반영 여부

| 1차 지적 | 현재 상태 |
|---|---|
| 1. 덮어쓰기 확인을 기다리다 제작이 멈춤 | 해결. "현재 대화에만 적용해 제작을 계속"으로 바뀜 |
| 2. 전역 저장 금지 문장의 위치 | 해결. 첫 문단의 공통 조건으로 옮김. 홈 폴더 전역 지침도 포함 |
| 4. 일반 채팅에서 원문을 다시 출력 | 해결. "스킬만 다운로드" 안내로 바뀜 |
| 5. 화면 표시 경로에서 상태가 바뀜 | 해결. `reusableOutputs`는 읽기만 하고, `syncRules`는 `outputs()`에만 있음. snapshot은 `composition('create',false)`로 만듦 |
| 6. `$&`·`{}` 문자 보존 | 해결. `fill`은 콜백 방식으로 한 번만 치환하므로 안전하고, 테스트도 추가됨 |
| 7. UI 과장 문구 | 대부분 해결. 남은 1건은 낮음 1 참고 |
| 3. 기존 자료의 기본값 켜짐 | 사용자가 결정한 사항이라 다시 지적하지 않음 |

## 중요도 중간

### 1. 프로젝트 지침 저장(3단계)에 중복·충돌 처리 규칙이 없음

**근거:**
- `TEMPLATES.setup` 2단계(스킬)에는 두 규칙이 있습니다.
  - "같은 내용이 이미 있으면 재사용"
  - "다른 내용은 보존하고 현재 대화에만 적용"
- 3단계(프로젝트 지침)에는 "저장하세요. 기존의 다른 지침은 보존하세요."만 있습니다.

**결과:**
- 설정 요청은 기본으로 켜져 있어서 create 요청을 보낼 때마다 다시 실행됩니다.
- 에이전트형 도구에서는 AGENTS.md나 CLAUDE.md 같은 파일에 같은 지침이 요청 때마다 덧붙습니다.
- 지침 내용이 조금씩 달라지는 경우가 많아서(중간 4 참고) 서로 어긋나는 판본이 여러 개 쌓일 수 있습니다.
- "보존하세요"라는 표현은 덧붙이기를 막지 못합니다.

**제안 (문구만 수정):** 3단계에 2단계와 같은 규칙을 넣으세요.

> 같은 업무용 지침이 이미 있으면 새로 추가하지 마세요. 내용이 다르면 기존 지침을 고치지 말고 새 원문은 현재 대화에만 적용하세요.

### 2. 첫 문장·마지막 문장·자료 안내가 질문 방식과 충돌함

**근거 1: `composition()`의 고정 문장**
- 첫 문장(`lead`)은 "아래 조건에 맞춰 자료를 만들어 주세요."입니다. 그런데 Grill 모드의 첫 지시는 "지금은 질문부터"입니다.
- 마지막 문장(`tail`)은 "필요한 정보만 짧게 질문하세요."입니다. 이 문장은 두 모드와 모두 부딪힙니다.
  - 초안부터 모드의 "추가 내용 질문 없이"와 정반대입니다.
  - Grill의 "애매한 부분을 함께 구체화"를 최소 질문으로 좁힙니다.
- 마지막 문장은 프롬프트 맨 끝에 있어서 AI가 가장 최근 지시로 강하게 따릅니다.

**근거 2: 참고자료 안내 (`referenceText()`, 첨부 모드)**
- "파일이 없거나 읽을 수 없으면 필요한 자료만 짧게 요청하세요."라고 지시합니다.
- 설정 요청을 켜 두면 setup 7단계의 "위 질문 방식에 따라 처리"가 이 지시를 덮습니다. 꺼 두면 덮어 줄 문장이 없습니다.

**근거 3: 초안부터 모드의 가리키는 대상이 없음**
- `draft` 문구는 `아래 지침의 "자료·정보가 없으면 먼저 요청"`을 가리킵니다. 하지만 이 문장은 프롬프트 어디에도 그대로 있지 않습니다.
- 실제로 해당하는 문장은 다음 넷입니다.
  - harness의 "없거나 읽을 수 없으면 먼저 요청하세요"
  - harness의 "결과를 크게 바꾸는 정보만 빠졌을 때 질문하고"
  - `referenceText`의 자료 요청 문장
  - `tail`의 질문 문장
- 설정 요청을 끄면(`setupReusable=false`) 아래에 재사용 원문 자체가 없습니다. 그래서 '아래 지침'이 가리키는 대상이 사라집니다. 테스트는 이 조합을 확인하지만, 금지 문구가 빠졌는지만 보고 이 문제는 잡지 못합니다.

**제안 (문구만 수정):**
- 첫 문장과 마지막 문장의 질문 부분을 모드와 상관없는 표현으로 바꾸세요. 예: "질문 여부와 순서는 맨 위 질문 방식을 따르세요."
- 초안부터 문구는 특정 문장을 인용하지 말고 범위로 지정하세요. 예: "이 요청문과 재사용 원문 안의 질문·자료 요청 지시는 이번 제작에서 [확인 필요] 표시로 대신하세요."

### 3. Grill로 정한 조건이 앱 기록과 검토 요청문에 남지 않음

**근거:**
- `conditionValues()`와 `conditionSnapshot()`에는 질문 방식도, 질문에 대한 답도 들어가지 않습니다.
- 검토 요청문(`composition('review')`)에는 확정 사항(`decisions`)이 붙지 않습니다. 확정 사항은 이어하기(resume)에만 붙습니다.

**결과:**
- Grill 대화에서 "그림 대신 표로", "8문항으로" 같은 조건을 바꿔 만든 결과를 새 채팅에서 검토하면, 검토 AI는 앱에 원래 입력된 조건과 대조합니다.
- 그래서 대화에서 의도적으로 바꾼 부분이 '수정 필요'로 잘못 판정될 수 있습니다.
- 앱은 조건이 그대로라고 판단하기 때문에(`conditionDifference`가 'same'을 반환) 경고도 나오지 않습니다.
- 질문 방식을 snapshot에서 뺀 것 자체는 맞습니다. 다만 Grill로 바뀐 조건을 다시 앱에 들일 경로가 없습니다.

**제안 (가장 작은 방법):**
- Grill 문구에 다음을 추가하세요: "결과물 끝에 '대화로 확정한 조건'을 짧게 목록으로 남기세요."
- 검토 요청문에도 확정 사항이 있으면 함께 넣으세요. 이미 있는 확정 사항(`decisions`) 칸을 재사용하면 됩니다.

### 4. 스킬 이름이 겹치고 내용이 자주 달라져서, 저장된 스킬이 사실상 처음 판본에 고정됨

1차 검토의 지적은 일부만 해결되었습니다. 덮어쓰지 않게 보호하는 문구는 들어갔지만, 아래 원인은 그대로입니다.

**근거:**
- 이름 `skillName=()=>teacher-${state.type}`은 자료 유형만 반영합니다. 과목이 달라도 같고, 수업용 직접 입력과 업무용 직접 입력도 둘 다 `teacher-custom`이 됩니다.
- 스킬 설명(description)도 유형만 반영합니다.
- 다음 경우에는 같은 수업 안에서도 스킬 본문이 바뀝니다.
  - `reuse.title`에 붙는 `(v2)`
  - `skillList(v,true)`의 `activeAuto(v)`
  - `gateList(v,true)`의 `qgOn(k,v)`
  - 이 셋은 이번 요청의 값(`v`)에 따라 켜지거나 바뀝니다.

**결과:**
- 처음 저장한 판본이 다른 내용을 가진 기존 스킬로 계속 남습니다.
- 그 뒤의 피드백("다음에도" 적용)은 현재 대화에만 적용됩니다.
- 다음 채팅에서는 옛 스킬이 자동으로 불립니다. 다른 과목의 고정 상황이 섞일 수도 있습니다.
- 교사는 AI의 상태 보고 한 줄을 놓치면 새 규칙이 저장되었다고 생각하게 됩니다.

**제안:**
- 최소 수정: 2단계의 '내용이 다를 때' 상태 보고를 다음처럼 바꾸세요. "기존 스킬을 새 원문으로 바꾸려면 '스킬을 새 내용으로 바꿔줘'라고 요청하라"고 한 줄로 안내하게 합니다. 사용자가 따로 요청해야 기존 설정을 고친다는 원칙을 유지하면서 갱신 경로가 생깁니다.
- 이름 구성(교과나 고정 정보 포함)을 바꾸는 것은 범위 결정이라 선택 사항입니다.

## 중요도 낮음

1. **초안부터 모드의 도움말이 결과를 보장하는 것처럼 읽힘**
   - `questionModes.draft.help`의 "불확실한 사실은 확인 필요로 남겨요"는 앱이 그렇게 보장한다는 말로 읽힙니다.
   - "남기도록 요청해요"로 바꾸면 다른 옵션의 문구와 어조가 맞습니다.
2. **두 옵션이 새 수업으로 넘어가는 방식이 다름**
   - 설정 요청 해제(`setupReusable`)는 새 수업에도 이어집니다.
   - 질문 방식은 수업 단위 맥락에 저장되므로 새 수업에서 '필요한 것만 질문'으로 돌아갑니다. 테스트도 이 동작을 의도한 것으로 확인합니다.
   - Grill을 선호하는 교사는 새 수업마다 다시 골라야 합니다. 의도한 동작이라면 도움말에 한 줄로 알려 주세요.
3. **고정 정보가 AI 환경에 자동으로 저장됨**
   - 이전에는 교사가 지침을 직접 붙여 넣었습니다. 이제는 '다음에도 유지할 정보'로 체크한 항목(예: 학급 특성)도 AI가 프로젝트에 저장하도록 요청됩니다.
   - `setupHelp`에 "유지하도록 체크한 정보도 함께 저장돼요"를 한 줄 추가하기를 권합니다.
4. **전달 기록이 커짐**
   - 설정 블록에는 스킬 원문 전체가 들어갑니다.
   - `lastTransfer`와 `lastRequest`의 실제 전달 블록(`sentBlocks`)은 같은 객체를 가리키지만, 저장할 때는 따로 직렬화됩니다. 같은 내용이 `resultRecord`, `resultHistory`, `checkRecord`의 snapshot에도 복제됩니다.
   - 결과 기록이 계속 쌓이면 localStorage 한도에 더 빨리 닿습니다. 저장 실패는 화면에 표시되므로 데이터가 손실되지는 않습니다.
5. **복사 경로에서 `syncRules`가 호출되지 않음 (미확인)**
   - 복사(`selectedOutput()`, 탭 0)는 `syncRules` 없이 `composition()`을 부릅니다. 다운로드하는 SKILL.md는 `outputs()`를 거쳐 `syncRules`를 통과합니다.
   - 규칙 배열이 정렬되지 않은 상태에서 복사하면, 요청문에 든 스킬 원문과 내려받은 SKILL.md가 다를 수 있습니다.
   - 테스트는 `outputs()` 이후 상태에서만 비교합니다. `syncRules`의 본문은 보지 못했습니다.
6. **"이미 정한 내용은 다시 묻지 마세요"의 범위**
   - Grill 문구의 "웹앱에서 이미 정한 내용은 다시 묻지 마세요"는 '서로 충돌하는 부분 찾기'와 부딪힐 수 있습니다.
   - "서로 충돌하지 않는 한"을 덧붙이면 됩니다.
7. **초안부터 모드의 "기존 파일 변경 확인"**
   - setup 2단계는 기존 파일을 바꾸지 말라고 합니다. 그런데 초안부터 모드는 "기존 파일 변경 확인"을 언급해서, AI가 기존 파일을 바꿔도 되는지 묻도록 유도할 수 있습니다.
   - "권한 승인"만 남기면 됩니다.
8. **결과 화면 안내가 Grill 첫 답변과 맞는지 (미확인)**
   - `handoffSteps`, `workflowText`의 문구를 보지 못했습니다.
   - "붙여넣으면 결과가 나와요" 같은 문구가 있다면 Grill 모드에서는 첫 답변이 질문이라는 점과 어긋납니다.
   - 같은 맥락으로, 설정 요청을 꺼도 `reuseChoices`의 "AI가 설정을 저장하지 못했을 때"라는 안내는 그대로 보입니다.

## 순서·저장·기록 점검에서 통과한 항목

- **블록 순서:** create 요청은 질문 방식 → 설정 요청 → 이번 조건 순서입니다. 설정 블록은 "위 질문 방식에 따라 제작으로 넘어갈 때"로 시작하고, Grill은 "질문이 끝나기 전에는 실행하지 마세요"라고 해서 서로 맞습니다. 수정·이어하기·검토 요청에는 두 블록이 붙지 않습니다.
- **영구 저장 범위:** 이번만 쓰는 정보(주제·차시·성취기준·발췌, 이번 요청 전용 방법)는 스킬 원문에서 빠집니다. 원문은 백틱 수를 계산한 코드 블록으로 감싸서 깨지지 않게 하고, 끝 표시로 경계를 나눕니다. 전역 메모리·맞춤 설정·홈 폴더 전역 지침·도구·패키지 설치는 모두 제외됩니다.
- **저장과 활성화의 구분:** 다시 읽어 확인하라는 지시, 상태 4종 보고, "활성화 미확인", "앱에 자동 전달 안 됨"이 모두 있습니다.
- **기록 분리:** 제작 요청 기록(`lastRequest.blocks`)과 점검 snapshot에는 준비 블록이 없고, 실제 전달 블록(`sentBlocks`)에만 남습니다. 그래서 옵션을 바꿔도 점검이 오래된 것으로 표시되지 않습니다.
- **앞선 개편의 반영:** 업무 그룹에서 수업용 문구가 섞이던 문제는 유형별 문구로 고쳐졌습니다.

## 테스트가 덮지 않는 부분

- 초안부터 모드에서 설정 요청을 끄고 참고자료를 첨부한 경우 (중간 2)
- 처음 저장한 뒤 `ver>1`이 되거나 자동 규칙이 바뀐 상태에서 다시 설정하는 경우 (중간 4)
- 복사 원문과 SKILL.md 다운로드가 같은지를 `syncRules` 이전 상태에서 비교하는 경우 (낮음 5)
- 실제 AI에서 동작하는지: Grill 진행, 스킬 등록, 프로젝트 지침 중복은 시험하지 않았습니다.

## 배포 판단
