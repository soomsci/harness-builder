# 컨텍스트 관리 개편 계획 검토

이 검토는 제공된 `index.html` 소스와 계획만 읽고 했습니다. 테스트, 브라우저 실행, 교사 사용 관찰은 하지 않았습니다. 표에는 근거 종류를 **[사실]**(소스에서 확인)과 **[추론]**으로 나눠 적었습니다.

---

## 1. 목적 기준 전체 판정

**조건부 찬성입니다. 다만 원안 그대로는 초보자 원칙과 충돌합니다.**

방향은 실제 문제를 겨냥합니다.
- **수업과 자료 분리:** 지금은 자료 종류를 바꾸면 방법과 기록이 지워집니다 [사실: `changeType`].
- **작업 종류별 요청문 구성:** 지금은 실행 요청과 검토 요청이 거의 같은 맥락을 반복합니다 [사실: `TEMPLATES.run`, `TEMPLATES.review`].
- **결과와 점검 연결:** 지금 점검은 결과물과 연결되지 않고 방법 버전(`ver`)에만 간접적으로 묶입니다 [사실].

하지만 원안은 저장 계층을 4단(기본 설정 / 수업 / 자료 / 결과 버전)으로 늘립니다. 질문 칸, 원칙 계층, 상태 4종 × 근거 3종도 함께 늘립니다. 초보자 부담 최소화라는 1순위 목적과 정면으로 부딪힙니다.

계획 전체를 관통하는 전제 하나를 바로잡아야 합니다.

> 앱이 맥락을 "관리"할 수 있는 지점은 **경계뿐**입니다. 첫 요청, 같은 수업의 다른 자료, 새 채팅, 다음 수업이 그 경계입니다. 같은 채팅 안에서는 AI가 이미 결과물과 맥락을 가지고 있습니다. 결과를 앱에 붙여 넣었다가 다시 복사하게 만들면 마찰만 늘어납니다.

**구현 전에 반드시 정해야 할 것**
1. 저장 구조와 삭제 범위. 지금 '새로 만들기'는 전체를 덮어씁니다.
2. 결과 본문을 저장할지, 저장한다면 얼마나 남길지.
3. 같은 채팅에서 고칠 때와 새 채팅에서 이어 할 때의 흐름 구분.
4. 분량 칸을 자료 단위로 옮기는 일. 지금은 기본 설정 칸입니다.

## 3. 원안 처리: 유지 / 변경 / 삭제 / 후속

| 처리 | 항목 |
|---|---|
| **유지** | 수업 아래에 자료를 두는 2계층 구조, 자료를 바꿔도 각 자료의 상태 보존, 새 수업에는 비고정 정보 제외, 작업 종류별 요청문(제작·검토·이어 하기), 새 결과에 이전 점검을 승계하지 않음, 피드백은 기본 '이번만', 원본을 보존하는 마이그레이션, 업무 문서는 별도 업무 |

| **삭제** | 사용자가 편집하는 '공통 반복 원칙' 계층(기존 `harness`의 '지킬 원칙'으로 충분), 1차의 '실행 검사 결과' 근거 유형, '요청에 담긴 정보 요약' 별도 영역(요청문 미리보기와 중복), 상단 흐름 재편 |
| **후속** | 참고자료 여러 개·발췌 선택·출처/쪽수 필드, 결과 전체 이력, PDF·PPT 자동 추출, 의미 검색, 평가·설명·시각자료 전용 질문, 앱 안 HTML 미리보기(채팅 도구가 이미 제공하므로 우선순위 낮음), 외부 에이전트 연동 |

## 4. '컨텍스트 엔지니어링'의 실질

**실제로 달라지는 것** (이런 것만 남겨야 함)
- **선택:** 작업 종류마다 다른 부분집합을 보냅니다. 제작에는 목표와 요구, 검토에는 결과와 기준, 이어 하기에는 확정 사항·최신 결과·남은 문제를 보냅니다. 지금은 실행 요청과 검토 요청이 같은 맥락을 반복합니다.
- **갱신:** 지금은 자료 종류를 바꾸면 '다음에도 쓰기' 방법까지 지워집니다 [사실: `changeType`이 `skills=[]`]. 바꾸면 종류별로 늘 쓰는 방법이 자료를 바꿔도 남습니다. 이것이 계획에서 가장 확실한 개선입니다.
- **차단:** 수업 경계로 차시·목표·오개념이 다음 수업에 넘어가지 않게 막습니다. 자료 경계로 분량이 다른 자료에 넘어가지 않게 막습니다.
- **전달:** 새 채팅용으로 그것만으로 완결된 꾸러미를 만듭니다.

**입력 폼과 긴 요청문만 늘리고 끝나는 위험이 있는 것**

원칙 계층, 상태·근거 조합, 요약 영역, 자료별 질문 증가가 여기에 해당합니다.

판정 기준은 하나입니다. 기능마다 다음 질문에 답할 수 있어야 합니다.

> "어느 출력의 어느 줄이 바뀌는가? 그 줄이 없으면 AI가 무엇을 틀리는가?"

답하지 못하면 넣지 않습니다.

**앱이 관측할 수 없는 경계**

UI는 이것을 확인했다고 표시하지 말고, 필요한 곳에서 AI에게 확인을 요청하는 문장으로 처리해야 합니다.
- 요청문을 실제로 붙여 넣었는지, 어느 채팅에 넣었는지
- 파일을 첨부했는지, AI가 그 파일을 읽었는지
- AI가 프로젝트 지침이나 기억을 썼는지
- AI가 웹 검색 등 도구를 실제로 썼는지
- 붙여 넣은 결과가 어느 요청에서 나왔는지, 잘리지 않고 전부 들어왔는지

결과와 요청의 연결은 교사가 '마지막으로 복사한 요청'을 기본값으로 확인하는 것까지만 가능합니다.

## 5. 초보자 여정 검토

**A. 첫 웹앱 만들기**
1. 'HTML 웹앱'을 고릅니다.
2. 질문 3개에 답합니다: 학년, 학습 목표, 학생이 화면에서 할 일.
3. 추천 방법이 이미 켜져 있으니 그냥 넘어갑니다.
4. 요청문을 복사해 AI에 붙여 넣습니다.

- **줄일 마찰:** 웹앱 전용 질문 3개를 기존 질문 3개에 더하면 6개가 됩니다. 총 3개를 넘기지 마세요.
- **줄일 마찰:** 결과 화면에 "AI 채팅의 미리보기로 확인하거나 파일로 저장해 여세요" 한 줄을 둡니다.

**B. 같은 수업으로 학습지 추가**
1. 결과 화면에서 '이 수업으로 다른 자료 만들기'를 누릅니다.
2. 학습지를 고릅니다. 수업 정보는 미리 채워져 있습니다.
3. 학습지 질문 1개(쪽수·정답 분리)에 답합니다.
4. 요청문을 복사합니다.

- **줄일 마찰:** '같은 채팅인지 새 채팅인지'를 묻지 마세요. 요청문은 항상 그것만으로 완결되게 만듭니다. 같은 채팅에 중복 맥락이 들어가도 해가 없습니다.
- **줄일 마찰:** PPT 분량이 따라오지 않아야 합니다.

**C. AI 결과를 받아 고치기**
- **같은 채팅:** 교사는 앱에서 고칠 점만 적습니다. '같은 채팅에 보낼 짧은 수정 요청'을 복사합니다. '다음에도 적용'을 고른 것만 방법에 저장됩니다.
- **결과 붙여넣기:** 선택 기능입니다. 새 채팅에서 이어 하거나 검토를 맡길 때만 필요합니다.

- **줄일 마찰:** 결과를 붙여 넣지 않아도 수정 요청을 만들 수 있어야 합니다.
- **줄일 마찰:** 지금처럼 방법을 고친 뒤 전체 요청문을 다시 복사하게 하는 흐름은, 같은 채팅에서는 결과를 처음부터 다시 만들게 합니다.

**D. 새 채팅에서 이어 하기**
1. 수업과 자료를 고릅니다.
2. '이어 하기 요청문'을 복사합니다. 확정 사항, 최신 결과(붙여 넣었다면), 남은 문제, 다음 할 일이 담깁니다.
3. 결과가 파일이면 "최신 파일을 첨부하고, 받았는지 먼저 말해 달라"는 문장이 들어갑니다.

- **줄일 마찰:** 화면에 "마지막 결과: 결과 2, 10/18, 312줄"을 보여 줘 잘못된 버전을 고르지 않게 합니다.

## 6. 권장 최소 첫 배포 범위와 순서

원안 순서(1→2→3→4→5→6, UI 검증은 맨 마지막)는 부적절합니다. 이유는 두 가지입니다.
- 교사가 '수업/자료' 개념을 이해하지 못하면 1~5번 구조가 모두 쓸모없어집니다. 이 위험은 UI에서 가장 먼저 드러납니다.
- 데이터 손실은 되돌릴 수 없으므로, 저장 안전 검사는 UI보다 먼저 확정해야 합니다.

**권장 순서**
1. **여정 대본 4개(5번의 A~D)와 390px 정적 화면 시안.** 교사 1~2명에게 말로 보여 주고 막히는 곳을 찾습니다.
2. **저장 구조와 마이그레이션, 그 검사.**
   - 새 키 `v2`에 다음 구조를 둡니다: `lessons[]`(ctx, fixed) / `materials[]`(lessonId, type, 분량, 이번만 규칙, 점검, 요청 지문) / `typeMethods{type}` / 결과 본문은 별도 키.
   - v1은 읽기만 합니다.
   - 삭제 범위 분리와 두 키 감시를 함께 구현합니다.
3. **A~D 한 바퀴만 구현.** 대상은 웹앱·PPT·학습지 3종입니다.
   - '이 수업으로 다른 자료', '새 수업'(고정 칸 복사)
   - 같은 채팅용 수정 요청, 이어 하기 요청문
   - 결과 붙여넣기(선택), 참고자료 첨부 확인 문장
4. **기존 자체 검사, 새 회귀 검사, 데스크톱·390px·키보드·내려받기 실기 검수.**
5. **배포 승인 요청.**

**2차로 미룰 것:** 참고자료 본문 칸, 맥락 변경 뒤 '확인 안 됨' 표시, 나머지 자료 종류의 전용 질문.
- 다만 맥락 지문 기록은 2번 단계의 저장 구조에 미리 넣어 두세요. 나중에 넣으면 마이그레이션을 한 번 더 해야 합니다.

## 7. 관찰 가능한 완료 기준과 시험 사례

**정상 사례**
- **마이그레이션:** v1 예시(`EXAMPLES`) 상태를 이전한 뒤 출력 5종이 이전 전과 같습니다. 의도한 추가 문장만 다릅니다. v1 원본은 바이트 단위로 그대로입니다.
- **같은 수업 다른 자료:** PPT의 '슬라이드 10장'이 학습지의 모든 출력에 없습니다. PPT → 학습지 → PPT로 돌아오면 PPT의 방법, 이번만 규칙, 최신 결과가 그대로입니다.
- **새 수업:** 이전 수업의 차시·목표·오개념·이미 아는 것이 출력 5종 어디에도 없습니다. 학년·교과는 남아 있습니다.
- **새 결과:** 결과를 새로 붙여 넣으면 점검이 미확인으로 돌아갑니다. 이전 점검은 기록에 남습니다.
- **이번만 피드백:** 일회성 피드백이 기본 설정과 스킬 파일에 없습니다(기존 검사 유지).
- **결과가 파일인 경우:** 이어 하기 요청문에 "첨부해 주세요"와 "받았는지 먼저 말해 달라"가 있습니다. "첨부했습니다"라는 표현은 없습니다.
- **추천 방법:** 새 자료에서는 추천 방법이 켜져 있습니다. 이전한 기존 자료의 방법 목록은 바뀌지 않습니다.

**실패 사례**
- 결과 키 저장 시 용량 초과 → 작은 상태는 저장되고 오류가 표시됩니다. 붙여 넣은 텍스트는 화면에 남아 내려받을 수 있습니다.
- v1이 손상됨 → 기존 복구 경로가 동작하고, v2에는 쓰지 않습니다.
- 다른 탭이 v2를 수정함 → 이 탭은 자동 저장을 멈춥니다.
- 이전을 두 번 실행 → 수업과 자료가 중복되지 않습니다.
- '이 자료 비우기' → 다른 수업과 자료는 그대로입니다.
- '모두 지우기' → v2, v1, 복구본, 결과 키가 모두 사라집니다. 확인 대화상자에서 취소하면 아무것도 지워지지 않습니다.
- 결과를 붙여 넣지 않았고 '파일 확인'도 하지 않음 → 검토 완료 표시가 나타나지 않습니다.
- 수업 목표를 수정 → 그 전에 점검한 자료에 '수업 정보가 바뀐 뒤 확인 안 됨'이 표시됩니다(2차).
- 클립보드 실패와 인쇄 실패 경로가 기존처럼 동작합니다.

**사용자 효용 평가** (수치 향상은 주장하지 않음)
- 같은 과제를 현재 버전과 새 버전으로 교사 2~3명이 수행합니다.
- 기록할 것:
  - 복사·붙여넣기 횟수
  - 이미 적은 정보를 다시 입력한 횟수
  - 잘못된 버전이나 이전 수업 정보가 섞인 사례
  - AI가 이미 받은 정보를 다시 물은 횟수
  - 막혀서 멈춘 화면과 그 이유
- 결과물 품질 비교는 이번 범위가 아닙니다. 보고서에 "미검증"으로 적으세요.

| 추천 방법 | 새 자료에만 기본 적용, 생성 시점의 문장을 복사 |
| 첫 슬라이스 | 웹앱·PPT·학습지 |

**사용자에게 꼭 물어야 하는 것** (3개)
1. **AI 결과물 본문을 이 브라우저에 저장할까요?**
   - 저장하면 새 채팅에서 이어 하기가 쉬워집니다.
   - 대신 공용 PC에서 결과 속 개인정보가 다음 사람에게 보일 수 있습니다.
   - 선택지: 저장 / 선택 시에만 저장(권장) / 저장 안 함.
2. **'새로 만들기'의 기본 동작은 무엇으로 할까요?**
   - 권장: '이 자료만 비우기'를 기본으로 하고, 공용 PC용 '모두 지우기'는 별도 버튼으로 둡니다.
   - 개인 PC의 데이터 보존과 공용 PC의 개인정보 보호가 맞부딪히는 정책 결정입니다.
3. **배포 전에 실제 교사 1~2명에게 왕복 시나리오를 시험해 볼 수 있나요?**
   - 어렵다면 본인 시연으로 대신하고, 보고서에 그 한계를 적겠습니다.

추천 방법 기본 적용과 '자료 종류별 늘 쓰는 방법' 보존은 기존 명세와 다른 동작입니다. CLAUDE.md의 10-18 개편 원칙(초보자 우선)으로 설계자가 정할 수 있는 범위로 판단했습니다. 다만 구현 보고 때 명세와 다르게 정한 것으로 함께 알려 주세요.
