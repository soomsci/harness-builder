## 판정: **통과**

배포를 막을 문제는 없습니다. 아래 남은 문제는 모두 [하] 수준입니다.

지난 검토의 7개 항목과 추가 단순화 3건은 모두 의도대로 반영된 것을 코드에서 확인했습니다. 저는 코드만 읽었고, 실행 결과는 선생님이 알려 주신 내용을 기준으로 했습니다.

- **조건 비교:** 실제 전달 블록의 key/text만 비교하고, 라벨 차이는 무시합니다.
- **결과 이름:** 이름이 빈칸이거나 기존 이름 그대로면 다음 회차 이름을 제안합니다. 처리 도중 이름이 바뀌면 등록하지 않고, 이전 이력도 보존됩니다.
- **이전 file 도구:** 명시적인 none/excerpt와 저장된 발췌는 보존합니다.
- **빈 점검 기록:** 판정·근거가 모두 비면 보관하지 않아, 새 결과의 `checkHistory`가 0개로 유지됩니다.

## 유효한 남은 문제

1. **[하·접근성] 결과를 등록하면 포커스가 사라집니다.** 6번과 같은 종류의 문제입니다.
   - 원인: `render('feedback-checks',false)`가 `<details>`에 focus를 보내는데, Safari와 Chrome에서 `<details>`는 tabindex가 없으면 포커스를 받지 못합니다.
   - 수정: render의 focus 줄에서 `details`를 만나면 그 안의 `summary`에 포커스를 주면, 다른 호출 경로도 함께 해결됩니다.
     `const t=el.tagName==='DETAILS'?el.querySelector('summary'):el;t.focus(...)`

2. **[하] 이전 file 도구의 이전 처리가 같은 수업의 다른 자료에도 퍼집니다.**
   - 원인: `textbookMode`는 `stashMaterial`에서 수업 단위 `l.ctx`에 저장됩니다.
   - 영향: 업무 문서 수업에서 file 도구를 쓰던 자료 A를 열면 수업 전체의 모드가 'attach'로 바뀝니다. 같은 수업의 자료 B(원래 none)도 첨부 안내가 붙고, B에 점검 기록이 있으면 '조건 변경' 경고가 뜹니다. 수업 자료형은 원래 기본값이 attach라서 영향이 없습니다.
   - 판단: 공유 맥락은 수업 단위라는 설계와 맞고, 첨부 안내에 "자료 없이 진행하라고 하면…"이 있어 피해는 작습니다. **수용을 권합니다.** 자료별로 모드를 따로 저장하는 것은 이번 범위 밖입니다.

3. **[하·정보량] attach 모드에서 같은 안내가 두 번 나옵니다.**
   - 위치: `referenceView`의 상단 "파일은 AI 채팅에 직접 첨부해요."와 하단 "요청문을 붙여 넣을 AI 채팅에 파일도 함께 첨부하세요."
   - 수정: 하단 문장을 `''`로 바꾸면 됩니다.

4. **[선택] 화면의 이름과 실제 등록 이름이 다를 수 있습니다.**
   - 2차 이후 "새 결과 등록" 입력칸에는 현재 이름("…·1차")이 보이는데, 버튼을 누르면 "…·2차"로 등록됩니다.
   - 확인창에 등록할 이름이 나오므로 실제 피해는 없습니다. 그대로 둬도 됩니다.

## 참고 (문제 아님)
- 실제로 문장이 바뀐 사용자만 다시 확인 대상(app)이 됩니다. 이번 개편에서 `procedureText`나 첨부 안내 문장 자체를 고쳤다면 그 사용자 전원이 대상이 되는데, 이는 의도한 의미와 맞습니다.
- 6번(모드 전환 포커스)과 위 1번에는 단언이 없습니다. 각각 단언 하나씩 추가하면 충분합니다.
