### 4. 오늘 나올 용어, 한 장으로 미리 보기

| 용어 | 쉬운 뜻 | 학교에 비유하면 |
|---|---|---|
| Prompt | AI에게 보내는 요청 문장 | 새 선생님께 건네는 지시 한마디 |
| Context | AI가 참고하는 배경 정보 전체 | 인수인계 자료 (진도표, 학급 특이사항) |
| Skill | 반복 업무를 하는 방법을 저장한 것 | 업무 매뉴얼, 체크리스트 |
| Tool | AI가 파일·검색·이미지 등을 직접 쓰는 능력 | 업무용 PC, 학교 시스템 계정, 복사기 |
| Agent | 목표를 받으면 여러 단계를 스스로 진행하는 AI | 준비부터 마무리까지 알아서 하는 선생님 |
| Harness | 위의 모든 것을 갖춘 AI의 업무 환경 | 자료·매뉴얼·검토 절차가 갖춰진 교무실 |

- AI = ‘똑똑하지만 우리 학교 사정은 전혀 모르는, 새로 오신 선생님’

**발표자 노트**

> 오늘 연수 내내 쓸 비유를 소개합니다. AI를 '우리 학교에 새로 오신 기간제 선생님'이라고 생각해 보세요. 이 선생님은 아주 똑똑하지만 우리 학교, 우리 반 사정은 하나도 모릅니다. Prompt는 그 선생님께 건네는 지시 한마디입니다. Context는 인수인계 자료, 즉 학급 명렬표와 진도표, 학생 특이사항 같은 것입니다. Skill은 '우리 학교는 학습지를 이렇게 만든다' 같은 업무 매뉴얼이고, Tool은 업무용 컴퓨터, 나이스 계정, 복사기 같은 사용 권한입니다. Agent는 하나하나 묻지 않고 준비부터 마무리까지 알아서 해 주는 선생님이고, Harness는 매뉴얼·자료·검토 절차가 잘 갖춰진 교무실 환경 전체라고 보시면 됩니다.

## 01 바이브 코딩

### 6. 그런데 AI 활용 방식이 달라지고 있다

| 단계 | 방식 | 예 |
|---|---|---|
| 챗봇 | 질문 → 답변 | 수행평가 일정 물어보기 |
| 생성형 AI | 요청 → 콘텐츠 생성 | 학습지·이미지 만들기 |
| 바이브 코딩 | 목표 → 프로그램 생성 | 퀴즈 웹앱 만들기 |
| Agent | 목표 → 여러 단계 실행 | 자료 찾고·만들고·검토 |
| **Harness** | **AI가 일하는 환경 자체를 설계** | 우리 학교용 AI 설정 |

**발표자 노트**

> 그런데 최근 몇 년 사이 AI를 쓰는 방식이 빠르게 바뀌고 있습니다. 처음에는 묻는 말에 답하는 챗봇이었다가, 글과 그림을 새로 만들어 주는 생성형 AI가 되었고, 말로 설명하면 프로그램까지 만들어 주는 바이브 코딩이 등장했습니다. 지금은 목표만 주면 여러 단계를 알아서 진행하는 에이전트가 나왔고, 그래서 이제는 'AI가 일하는 환경 자체를 설계하는 것'이 중요해졌습니다. 오른쪽 계단으로 갈수록 사람이 하나하나 시키는 부분은 줄고, AI에게 맡기는 범위는 넓어진다고 보시면 됩니다.

### 7. 바이브 코딩: 무엇을 만들지 말하면 AI가 코드를 쓴다

| 전통적 개발 | 바이브 코딩 |
|---|---|
| 사람 — 설계 | 사람 — 무엇을 만들지 설명 |
| 사람 — 코드 작성 | AI — 코드 생성 |
| 사람 — 테스트 | |

- 예) “학생 이름을 넣으면 발표자를 랜덤으로 뽑아 주는 웹페이지를 만들어 줘”

**발표자 노트**

> 바이브 코딩(Vibe Coding)은 '느낌(vibe)대로 말하듯' 원하는 것을 우리말로 설명하면 AI가 코드를 대신 써 주는 방식입니다. 예전에는 프로그램을 만들려면 사람이 직접 설계하고, 코드를 한 줄 한 줄 쓰고, 테스트까지 해야 했습니다. 지금은 '학생 이름을 넣으면 랜덤으로 발표자를 뽑아 주는 웹페이지를 만들어 줘'라고 말하면 실제로 작동하는 페이지가 나옵니다. (시연: 미리 만들어 둔 바이브 코딩 결과물을 보여 주세요. 가능하면 즉석에서 간단한 요청을 해 보면 효과가 큽니다.)

### 9. ‘경계선’에 담긴 교사의 결정 여섯 가지

| 교사가 정한 것 | 앱에서는 | 수업 설계로 보면 |
|---|---|---|
| 원리 → 데이터 | 원리를 먼저 배우고, 데이터는 그다음에 | 수업 흐름 설계 |
| 화산 → 지진 → 비교 | 한 번에 하나씩 보기 | 단계적 발판 |
| 탐구 질문 | “화산 없는 경계는 왜?” | 깊은 사고 유도 |
| 신뢰도 선택 | 낮음 · 보통 · 높음 | 자기 판단 돌아보기 |
| 고정관념 검증 | “한반도엔 지진이 없다?” | 오개념 다루기 |
| 모둠 코드 | 노트북 한 대로 함께 | 학급 운영 |

- 코드는 AI가 썼지만, 이 여섯 가지 결정은 모두 교사가 했습니다.

**발표자 노트**

> 이 앱에서 눈여겨보실 점은 기능이 아니라 그 안에 담긴 수업 설계입니다. 코드는 AI가 썼지만, 무엇을 어떤 순서로 넣을지는 모두 교사가 정했습니다. 첫째, 데이터부터 보여 주지 않고 원리를 먼저 배우게 했습니다. 둘째, 화산 → 지진 → 둘을 겹쳐 비교하는 순서로 한 번에 하나씩 보게 해서 학생이 패턴을 찾기 쉽게 했습니다. 셋째, '지진은 많지만 화산이 없는 경계가 있을 수 있는 까닭은?'처럼 생각을 깊게 하는 탐구 질문을 넣었습니다. 넷째, 경계선을 그린 뒤 신뢰도를 고르게 해서 학생이 자기 판단을 돌아보게 했습니다. 다섯째, '한반도에는 지진이 발생하지 않는다'는 고정관념을 데이터로 검증하게 했습니다. 마지막으로 모둠 코드로 한 모둠이 노트북 한 대로 함께 참여하도록 학급 운영까지 고려했습니다. 이것이 바로 '교사의 전문성을 소프트웨어로 표현한다'는 말의 실제 모습이고, 이 결정들이 오늘 배울 Context와 Skill입니다.

### 10. ‘경계선’ 제작: 설계와 검증은 교사가, 코드는 AI가

**교사가 정한 것**

| 할 일 | Context · 상황 | Skill · 방법 |
|---|---|---|
| 데이터로 판 경계를 직접 찾는 탐구 도구 | 판 구조론 단원 / 모둠별 노트북 한 대 / 오개념: 한반도엔 지진 없다 | 원리 먼저 / 화산 → 지진 → 비교 / 정답은 먼저 보여 주지 않기 |

**AI가 한 것**

| Tool · 도구 | Agent |
|---|---|
| ChatGPT · Claude / USGS 데이터 · Firebase | 기능을 하나씩 만들고 확인 |

**확인하고 고친 것**

| 확인 기준 | 피드백 (시범 운영 후 고친 것) |
|---|---|
| 위치·과학 내용 정확? / 개인정보 없음? | TEST로 시범 운영 → 참여 방식 수정 |

**발표자 노트**

> 이 앱을 만든 과정을 하네스의 단계로 정리하면 이렇습니다. 위 줄은 교사가 정한 것입니다. 목표는 학생이 데이터로 판 경계를 직접 찾는 탐구 도구였고, AI에게는 판 구조론 단원, 모둠별 노트북 한 대라는 수업 환경, '한반도엔 지진이 없다'는 오개념 같은 상황을 알려 주었습니다. 그리고 원리를 먼저 배우게 하고, 화산·지진·비교 순서로 하나씩 보여 주고, 정답 경계는 먼저 보여 주지 않는다는 설계 원칙을 정했습니다. 아래 줄 왼쪽은 AI와 도구가 한 일입니다. ChatGPT와 Claude로 코드를 만들고, USGS 공개 데이터를 쓰고, Firebase로 배포했습니다. 한 번에 다 만들지 않고 기능을 하나씩 만들고 확인했습니다. 아래 줄 오른쪽은 확인하고 고친 과정입니다. 위치와 과학 내용이 정확한지, 개인정보가 없는지 확인했고, TEST 코드로 시범 운영한 뒤 수업 참여 방식을 모둠별 노트북 한 대로 고쳤습니다. 코드는 AI가 썼지만, 상황과 원칙과 기준은 교사가 만들었다는 것이 핵심입니다.

### 11. 바이브 코딩, 교사에게 좋은 점과 교육적 의미

**좋은 점**

1. 우리 반에 딱 맞는 도구
2. 아이디어를 바로 시제품으로
3. 수업 중 반응 보고 즉시 수정
4. 유료 앱 없이, 비용 부담 감소
5. 동료와 나누기

**교육적 의미 — 무엇이 바뀌나**

- 교사: 소비자 → **설계자**
- 수업: 모두 같은 자료 → **수준별 자료**
- 학생: 코드 문법 → **문제 정의 · 검증**

**발표자 노트**

> 바이브 코딩이 선생님께 주는 좋은 점은 다섯 가지입니다. 우리 반에 딱 맞는 도구를, 아이디어가 떠오르면 몇십 분 안에 직접 만들고, 수업 중 학생 반응을 보고 바로 고칠 수 있습니다. 유료 앱 없이 필요한 기능만 만들 수 있고, 동료와 나눌 수도 있습니다. 그리고 이것이 교육적으로 갖는 의미는 세 가지입니다. 교사는 만들어진 도구를 고르는 소비자에서 수업에 맞는 도구를 설계하는 사람이 되고, 수업은 모두 같은 자료에서 수준별 자료로 바뀌고, 학생에게는 코드 문법보다 문제를 정의하고 결과를 검증하는 힘이 중요해집니다.

### 12. AI가 만든 도구도, 수업 전에 교사가 검토합니다

| 확인할 것 | 이런 일이 생길 수 있다 | 이렇게 한다 |
|---|---|---|
| 작동 검증 | 겉으로는 잘 돌아가도 계산이 틀리거나 멈출 수 있다 | 수업 전 여러 번 직접 눌러 보기 |
| 개인정보 | 이름·성적·상담 내용이 AI나 외부 사이트로 간다 | “1번 학생”처럼 바꿔서 사용 |
| 내용 정확성 | 시뮬레이션 수치, 연표가 틀릴 수 있다 | 교과 내용은 교사가 최종 확인 |
| 저작권 | AI가 넣은 이미지·글꼴·문제의 출처가 불분명하다 | 출처 확인, 직접 만든 자료 사용 |
| 배포 · 보안 | 학생에게 링크를 나눠 준다 | 학교·교육청 지침, 이용 연령 확인 |

**발표자 노트**

> 장점만큼 주의할 점도 분명합니다. 첫째, AI가 만든 프로그램은 겉보기에 잘 돌아가도 계산이 틀리거나 특정 상황에서 멈출 수 있습니다. 수업 전에 반드시 직접 여러 번 눌러 보세요. 둘째, 학생 이름·성적·상담 내용 같은 개인정보는 AI에 입력하거나 외부 사이트에 저장하지 않습니다. 이름이 필요하면 '1번, 2번'처럼 바꿔 쓰세요. 셋째, 과학 시뮬레이션의 수치나 역사 연표처럼 내용 자체가 맞는지는 교사가 확인해야 합니다. 넷째, AI가 넣은 이미지·글꼴·문제의 출처와 저작권을 확인합니다. 다섯째, 학생에게 링크를 배포하기 전에는 학교·교육청의 정보보호 지침과 서비스 이용 연령을 확인하세요.

### 13. 학생에게 쓰기 전에 · 학습지원 소프트웨어 학운위 심의

- 근거: 초·중등교육법 제29조의2 (2024. 8. 개정) · 2026학년도부터 적용 · 확인: 에듀집(edzip.kr)
- **Q1.** 학교 교육과정 운영(정규 교과 수업)을 위해 사용하나요?
  - 아니요 (방과후·돌봄 포함, 교사 업무용으로만) → 심의 불필요
  - 예 → Q2
- **Q2.** 학생의 개인정보를 수집·이용·처리하나요? (로그인, 성명·닉네임·학번·연락처·영상·학습이력 등)
  - 예 / 아니요 모두 → Q3까지 판단
- **Q3.** 교과 성취기준과 관련된 학습콘텐츠를 포함하며, 학교 교육과정 운영 지원을 목적으로 개발·보급되었나요?

| 개인정보 | 학습콘텐츠 | 결과 |
|---|---|---|
| ○ | ○ | 심의 필요 (필수기준 + 선택기준) |
| ○ | × | 심의 필요 (필수기준) |
| × | ○ | **심의 필요 (선택기준)** |
| × | × | 심의 불필요 |

- 우리 학교: 교사가 개발한 웹앱(경계선)은 ‘선택기준 활용 심의 대상’ → 학교운영위원회 심의를 받아 사용합니다.

**발표자 노트**

> 바이브 코딩으로 만든 도구든, 기업의 AI 코스웨어든, 학생이 수업에서 쓰게 하려면 꼭 확인해야 할 절차가 있습니다. 2024년 개정된 초·중등교육법 제29조의2에 따라, 학교장이 학습지원 소프트웨어를 교육자료로 선정할 때는 교육부 기준을 지키고 학교운영위원회 심의를 거쳐야 합니다. 심의가 필요한지는 세 가지 질문으로 판단합니다. Q1, 학교 교육과정 운영, 즉 정규 교과 수업에 쓰는가? 방과후나 돌봄, 교사 업무용으로만 쓴다면 심의가 필요 없습니다. Q2, 학생 개인정보를 수집·이용·처리하는가? 로그인, 이름, 닉네임, 학번, 연락처, 영상, 학습 이력 등을 받는다면 '예'입니다. Q3, 교과 성취기준과 관련된 학습 콘텐츠를 담고 있고 교육과정 운영 지원을 위해 만든 것인가? 이 두 질문의 답에 따라 필수기준과 선택기준 중 무엇으로 심의할지가 정해집니다. 개인정보를 받지 않고 학습 콘텐츠도 아니라면 심의가 필요 없습니다. 제가 만든 '경계선' 앱은 정규 과학 수업에 쓰고, 학생 개인정보는 받지 않고 모둠 코드로만 접속하지만, 판 경계라는 교과 성취기준과 관련된 학습 콘텐츠를 담고 있습니다. 그래서 '선택기준 활용 심의 대상'이고, 우리 학교는 학교운영위원회 심의를 받아 사용합니다. 직접 만든 웹앱도 예외가 아니라는 점, 꼭 기억해 주세요. 필수기준 충족 여부는 교육부가 운영하는 에듀집(edzip.kr)에서도 확인할 수 있습니다.

## 02 상황 (Context)

### 14. “너는 20년차 교사야” — 정말 효과가 있을까?

- 연구 결과
  - 2024 EMNLP: 역할(persona)을 추가해도 전반적 성능이 일관되게 향상되지 않음
  - 2025 EMNLP: 과제와 관련 없는 역할 설정에 모델이 민감하게 반응 → 성능 하락 가능
- **역할(페르소나)을 준다고 능력이 오르지는 않는다.**

**발표자 노트**

> 가장 유명한 프롬프트 팁은 아마 '너는 20년차 중학교 과학 교사야'처럼 역할, 즉 페르소나를 주는 것일 겁니다. 써 보신 분 많으시죠? 그런데 연구 결과는 생각과 다릅니다. 자연어처리 분야의 대표 국제 학회인 EMNLP에 2024년 발표된 연구에서는, 역할을 붙인다고 전반적인 정확도가 일관되게 올라가지 않았습니다. 2025년 연구에서는 오히려 과제와 상관없는 설정이 들어가면 모델이 민감하게 흔들리는 사례도 확인됐습니다. 신규 선생님 명찰에 '20년차 베테랑'이라고 붙여 준다고 수업 실력이 늘지 않는 것과 같습니다. 페르소나, 즉 '가면'을 바꿔 쓴다고 실력이 생기지는 않습니다.

### 15. 역할보다 중요한 것은 ‘무슨 일’인지 알려 주기

| ✕ 실력을 올려 달라는 주문 (효과 불분명) | ○ 어떤 관점으로 볼지 정하기 | ◎ 무슨 일인지 알려 주기 |
|---|---|---|
| ~~너는 20년차 중학교 교사야. 판 구조론 수업자료를 만들어줘.~~ | 교육과정 검토자의 관점에서 성취기준과 맞지 않는 부분만 지적하라. | 대상: 중1 / 선행학습: 대륙이동설 / 목표: 해저확장설의 근거 이해 / 수업시간: 45분 / 주의: 맨틀=액체 오개념 |

**발표자 노트**

> 역할을 주는 방식을 세 단계로 비교해 보겠습니다. 첫째, '너는 20년차 교사야, 판 구조론 자료 만들어 줘'처럼 실력을 올려 달라는 주문은 효과가 불분명합니다. 둘째, '교육과정 검토자의 관점에서 성취기준과 맞지 않는 부분만 지적하라'처럼 어떤 관점으로 볼지를 정해 주면 훨씬 낫습니다. 셋째, 가장 효과적인 것은 이번 일이 무슨 일인지 알려 주는 것입니다. 대상은 중1, 지난 시간엔 대륙이동설을 배웠고, 목표는 해저확장설의 근거 이해, 45분, 맨틀이 액체라는 오개념 주의. 대체 수업을 부탁할 때 '저 대신 수업 좀 해 주세요'보다 이런 메모를 남겨야 수업이 제대로 되는 것과 같습니다. 이것이 다음 장부터 볼 Context입니다.

### 16. 같은 AI, 다른 결과 · 시연에서 함께 비교하기

- **기본 요청:** 해저확장설 수업자료 만들어줘.
- **상황 (Context)을 넣은 요청:**

  ```
  대상: 중학교 1학년 | 이전 차시: 대륙이동설
  이번 차시: 해저확장설 | 다음 차시: 판의 경계
  학습목표: 해양지각의 나이 분포를 통해 해저확장설의 근거를 설명한다.
  학생들은 맨틀과 지각의 개념까지만 학습했다. 시각자료 중심.
  중앙해령 기준 해양지각 나이의 대칭적 증가 강조. ‘맨틀=액체’ 오개념 주의.
  ```

- 결과가 나오면 함께 표시해 보세요 (○ · △ · ✕)

| 볼 것 | 기본 요청 | 상황을 넣은 요청 |
|---|---|---|
| 중1 수준에 맞는가 |  |  |
| 해양지각 나이의 대칭이라는 핵심 근거가 있는가 |  |  |
| ‘맨틀 = 액체’로 읽힐 표현이 없는가 |  |  |
| 이미 배운 대륙이동설을 그대로 반복하지 않는가 |  |  |

**발표자 노트**

> 실제로 비교해 보겠습니다. 같은 AI에게 왼쪽은 한 줄만, 오른쪽은 수업 맥락을 함께 주었습니다. (시연: 두 요청을 실제로 입력하고 결과를 나란히 보여 주세요.) 왼쪽 결과는 대체로 교과서 요약 같은 일반적인 자료가 나오고, 학년 수준이 맞지 않거나 이미 배운 내용을 반복하기도 합니다. 오른쪽은 중1 수준에 맞춰, 해양지각의 나이가 중앙해령을 기준으로 대칭적으로 늘어난다는 핵심 근거에 집중하고, 맨틀을 액체처럼 표현하지 않도록 조심한 자료가 나옵니다. AI 실력은 같은데, 무엇을 알려 주었느냐에 따라 결과가 완전히 달라집니다.

### 17. Context Engineering (강조 장)

- **AI가 이 일을 하기 위해 무엇을 알고 있어야 하는가?**
- 원하는 결과를 위해 AI가 보게 되는 정보 전체를 구성하는 일.

**발표자 노트**

> 그래서 등장한 개념이 컨텍스트 엔지니어링입니다. 질문이 'AI에게 어떻게 말할까'에서 'AI가 이 일을 하려면 무엇을 알고 있어야 할까'로 바뀝니다. 좋은 문장 하나를 찾는 것이 아니라, AI가 일할 때 보게 되는 정보 전체를 구성하는 일입니다. 비유하면 프롬프트는 '지시 한마디', 컨텍스트는 '인수인계 파일 전체'입니다. 출장 가면서 대신 담임을 맡아 줄 선생님께 '잘 부탁해요'라고 말을 예쁘게 하는 것보다, 학생 명단·특이사항·오늘 일정·연락처가 담긴 파일을 건네는 것이 훨씬 중요한 것과 같습니다.

### 18. Context는 무엇인가?

- 가운데 **AI**를 둘러싼 10가지: 현재 요청 · 이전 대화 · 사용자 지침 · 첨부 파일 · 교육과정 · 기존 PPT · 검색 결과 · 사용 가능한 Tool · Skill · 출력 제약

**발표자 노트**

> 컨텍스트에는 생각보다 많은 것이 들어갑니다. 지금 입력한 요청뿐 아니라, 같은 대화창에서 앞서 나눈 대화, 미리 설정해 둔 사용자 지침, 첨부한 파일, 교육과정 문서, 기존에 만든 PPT, 검색 결과, AI가 쓸 수 있는 도구 목록, 저장해 둔 스킬, '3쪽 이내로' 같은 출력 제약까지 모두 AI가 판단할 때 보는 정보입니다. 예를 들어 대화창에서 앞서 '우리 반은 기초가 약해요'라고 말해 두었다면, 그다음 요청에도 그 정보가 영향을 줍니다. 반대로 새 대화창을 열면 그 정보는 사라집니다. 그래서 컨텍스트는 '지금 AI의 책상 위에 펼쳐져 있는 모든 자료'라고 생각하시면 됩니다.

### 19. 교사는 이미 Context를 가지고 있다

**교사의 머릿속**

1. 이 반 학생 수준
2. 지난 시간에 무엇을 배웠는지
3. 어디에서 자주 틀리는지
4. 교과서에서는 어떤 표현을 쓰는지
5. 45분 안에 어디까지 가능한지
6. 내가 좋아하는 자료 스타일

- **문제는 AI가 이것을 모른다는 것.**

**발표자 노트**

> 사실 선생님들은 이미 엄청난 컨텍스트를 가지고 계십니다. 이 반 학생들 수준이 어떤지, 지난 시간에 어디까지 했는지, 어느 문제에서 자주 틀리는지, 교과서에서는 어떤 용어를 쓰는지, 45분 안에 어디까지 가능한지, 내가 선호하는 자료 스타일이 무엇인지. 이런 건 선생님 머릿속에서는 너무 당연해서 굳이 말하지 않게 됩니다. 문제는 AI가 이것을 하나도 모른다는 점입니다. AI는 우리 반 교실에 한 번도 와 본 적이 없으니까요. 그래서 이 머릿속 정보를 글로 꺼내 AI에게 건네주는 것이 컨텍스트 엔지니어링의 출발점입니다.

### 20. 많이 넣는다고 좋은 Context는 아니다

| ✕ 맥락 오염 | ✓ 쓸모 있는 맥락 |
|---|---|
| 많은 문서 | 관련성 |
| 많은 지시 | 최신성 |
| 오래된 정보 | 우선순위 |
| 중복된 규칙 | 구조 |
| 관련 없는 자료 | 필요한 만큼만 |

**발표자 노트**

> 그렇다고 자료를 많이 넣을수록 좋은 것은 아닙니다. 관련 없는 문서, 너무 많은 지시, 작년 교육과정 같은 오래된 정보, 서로 겹치거나 충돌하는 규칙이 섞이면 AI가 오히려 헷갈립니다. 이것을 Context Pollution, '맥락 오염'이라고 부릅니다. 예를 들어 해저확장설 자료를 부탁하면서 1학기 전체 PPT 30개를 다 넣으면, AI가 엉뚱한 단원 내용을 섞어 버릴 수 있습니다. 좋은 컨텍스트는 이번 일과 관련 있고, 최신이고, 무엇이 더 중요한지 우선순위가 있고, 정리된 구조로, 필요한 만큼만 들어간 것입니다. 이삿짐 싸듯 다 넣지 말고, 출장 가방 싸듯 필요한 것만 골라 넣으세요.

### 21. 작성 예시: 상황 (Context)

| 항목 | 내용 | 항목 | 내용 |
|---|---|---|---|
| 교과 | 과학 | 이미 아는 것 ★★ | 지각·맨틀 구분까지만 (판은 아직) |
| 학년 | 중학교 1학년 | 오개념 ★★ | ‘맨틀 = 액체’ |
| 단원 | 판 구조론 | 학급 특성 | 그래프 해석이 약한 반 |
| 이전 차시 | 대륙이동설 | 수업 시간 | 45분 |
| 이번 차시 | 해저확장설 | 참고자료 | 교과서 52~55쪽 |
| 다음 차시 | 판의 경계 | 출력물 형태·분량 | A4 2쪽 학습지 |
| 학습 목표 | 해양지각 나이 분포로 해저확장설 근거 설명 | | |

- 앱에서 ‘수업 예시 (해저확장설 학습지)’를 누르면 이 내용이 그대로 채워집니다.

**발표자 노트**

> 하네스 빌더의 '상황' 단계에 들어갈 내용을 미리 보겠습니다. 중학교 1학년 과학, 판 구조론 단원의 해저확장설 차시 예시입니다. 핵심은 '학생들이 이미 알고 있는 것'과 '예상되는 어려움·오개념', 앱에서 별 두 개(★★)가 붙은 칸입니다. 이 두 칸이 AI 결과물의 수준을 가장 크게 바꿉니다. 예를 들어 '지각·맨틀 구분까지만'이라고 적으면 AI가 아직 안 배운 용어를 남발하지 않고, '맨틀 = 액체'를 적으면 오해를 부르는 표현을 피합니다. 앱의 '예시 불러오기' 버튼을 누르면 이 내용이 그대로 채워집니다.

### 22. 하네스 빌더 접속하기

- QR 코드 + harness-builder-py5b9.web.app
- ① **단계** — 업무 → 상황 → 방법 → 확인 기준 → 도구 → 완성
- ② **미리보기** — 입력할 때마다 바로 바뀐다
- ③ **예시 불러오기** — 막히면 해저확장설 예시부터
- ‘이전 입력이 남아 있어요’ 안내가 뜨면 → ‘새로 시작’
- 오른쪽 이미지: 하네스 빌더 첫 화면 (번호 ①②③ 표시)

**발표자 노트**

> 이제부터 실습은 '하네스 빌더' 웹앱에서 진행합니다. 휴대폰이나 노트북으로 왼쪽 QR 코드를 찍거나 주소를 입력해 접속해 주세요. 위쪽에 업무 → 상황 → 방법 → 확인 기준 → 도구 → 완성 순서가 보이고, 오른쪽에는 입력할 때마다 바로 바뀌는 미리보기가 있습니다. 막히면 아래쪽 '예시 불러오기'로 해저확장설 학습지 예시를 먼저 보셔도 좋습니다. 연수실 공용 컴퓨터에서 '이전에 입력한 내용이 남아 있어요'라는 안내가 뜨면, 앞사람의 입력일 수 있으니 '새로 시작'을 눌러 주세요. 실습을 마친 뒤에도 결과를 복사하거나 내려받고 나서 '처음부터 다시'를 눌러 비워 주시면 됩니다. 입력 내용은 그 컴퓨터의 브라우저에만 저장되고, 학생 이름이나 연락처는 넣지 않습니다.

### 23. 실습 1 · 업무 고르기 + 상황 채우기 (7분)

1. **업무 유형 고르기** — 학습지 · 수업 PPT · 가정통신문 …
2. **할 일 한 줄 쓰기** — 예) 매주 만드는 중1 과학 학습지
3. **상황 채우기** — ★★ 칸(이미 아는 것 · 오개념)부터

- 다 됐는지 확인: 상단 완성도 옆에 ‘핵심 칸을 모두 채웠어요’가 보이면 끝
- 오른쪽 이미지: 업무 단계 화면(①②), 상황 단계 ★★ 칸 화면(③)

**발표자 노트**

> 첫 번째 실습입니다. 하네스 빌더에서 먼저 업무 유형을 고르세요. 학습지, 수업 PPT, 가정통신문처럼 자주 반복하는 일이 좋습니다. 그리고 '할 일 한 줄'을 적습니다. 예를 들어 '매주 만드는 중1 과학 단원 학습지'처럼요. 다음 버튼을 누르면 '상황' 단계가 나옵니다. 별 두 개가 붙은 칸, 즉 학생들이 이미 알고 있는 것과 예상되는 오개념부터 채워 주세요. 빈칸이 있어도 괜찮습니다. 위쪽 완성도 표시와 '빠진 핵심 칸' 버튼을 보면 무엇을 더 채우면 좋을지 알 수 있습니다. 약 7분 드리겠습니다.

## 03 방법 (Skill)

### 24. Skill: 반복되는 방법은 저장해 둔다

- 정의: 반복되는 업무 방법을 AI가 재사용할 수 있게 저장해 둔 것. 예) 학습지 만들기

| Context · 매번 바뀜 | Skill · 매번 같음 |
|---|---|
| 이번 차시: 해저확장설 | 학습지 양식 (순서) |
| 이번 학습목표 | 문항 수와 유형 |
| 이번에 조심할 오개념 | 검토 기준 |

**발표자 노트**

> 매번 수업 상황 카드를 다 써야 할까요? 바뀌는 것과 바뀌지 않는 것을 나눠 보면 답이 보입니다. 학습지를 예로 들면, 이번 차시 내용, 이번 학습목표, 이번에 조심할 오개념은 매번 바뀝니다. 이것이 Context입니다. 반면 학습지 양식, 즉 학습목표 → 핵심 개념 → 그림 → 빈칸 5문항 → 서술형 1문항이라는 순서, 문항 수와 유형, 다 만든 뒤 검토하는 기준은 매번 똑같습니다. 이렇게 반복되는 방법을 저장해 둔 것이 Skill입니다. 요리로 치면 Context는 오늘 냉장고의 재료, Skill은 우리 집 레시피입니다.

### 25. 교사용 Skill 모음

|   | 이름 | 하는 일 | 예 |
|---|---|---|---|
| 01 | 수업 설계 도우미 | 수업 흐름 설계 | 도입-전개-정리 45분 배분 |
| 02 | 쉬운 설명 도우미 | 학생 수준에 맞게 설명 | 초등 5학년 눈높이로 바꾸기 |
| 03 | 시각화 도우미 | 개념을 시각자료로 변환 | 해양지각 나이 분포 그림 |
| 04 | 오개념 점검 도우미 | 잘못된 개념 찾기 | ‘맨틀=액체’ 표현 찾기 |
| 05 | 평가문항 도우미 | 평가문항 제작 | 난이도별 선택형 10문항 |
| 06 | 사실 확인 도우미 | 내용·출처 검토 | 수치·연도·인용 확인 |

- 이름은 우리말이어도 괜찮습니다. 이렇게 모아 두면 나만의 ‘스킬 서랍’이 됩니다.

**발표자 노트**

> 선생님들께 쓸모 있는 스킬을 이름을 붙여 정리해 보면 이런 목록이 됩니다. 수업 흐름을 설계하는 Lesson Planner, 학생 수준에 맞게 쉽게 풀어 주는 Concept Simplifier, 개념을 그림이나 도식으로 바꾸는 Visualizer, 오개념을 점검하는 Misconception Checker, 평가문항을 만드는 Assessment Builder, 내용과 출처를 검토하는 Fact Checker. 이렇게 이름표를 붙여 모아 두면 나만의 스킬 서랍장, Skill Library가 됩니다. 영어 이름이 부담스러우면 '수업설계 도우미', '쉬운설명 도우미'처럼 우리말로 붙여도 전혀 상관없습니다.

### 26. Skill은 실제로 이렇게 생겼다 · 학습지 만들기

```
이름: 주간 과학 학습지 만들기
언제 쓰나: 매주 단원 학습지가 필요할 때

학습지 양식 (A4 2쪽, 이 순서를 지킨다)
 ① 학습 목표 한 문장
 ② 핵심 개념 정리 (5줄 이내, 교과서 용어)
 ③ 그림 1개 (핵심 관계만)
 ④ 빈칸 채우기 5문항 (쉬운 것 → 어려운 것)
 ⑤ 서술형 1문항
 ※ 정답·해설은 별도 페이지

검사 목록
 □ 정답이 맞는가 □ 오개념 표현이 없는가 □ 2쪽 이내인가
```

- 오른쪽: 학습지 양식 그림 (중1 과학 학습지 · 해저확장설 — ① 학습 목표 ② 핵심 개념 정리 ③ 그림 ④ 빈칸 채우기 5문항 ⑤ 서술형 1문항)

**발표자 노트**

> 학습지를 만드는 Skill은 실제로 이렇게 생겼습니다. 코딩이 아니라 우리말로 쓴 업무 매뉴얼 한 장입니다. 이름과 언제 쓰는지, 그리고 학습지 양식을 순서대로 적었습니다. 학습 목표, 핵심 개념 정리, 그림 1개, 빈칸 채우기 5문항, 서술형 1문항, 그리고 정답과 해설은 별도 페이지. 마지막에 검사 목록을 붙였습니다. 오른쪽은 이 Skill로 만들어지는 학습지의 모양입니다. 왼쪽 글의 순서가 오른쪽 학습지의 칸 순서와 그대로 일치합니다. 이 글을 SenGPT 비서나 ChatGPT·Claude 프로젝트의 지침 칸에 저장해 두면, 다음부터는 '이번 차시 학습지 만들어 줘'라고만 해도 이 양식대로 나옵니다.

### 27. 같은 Skill, 다른 차시 → 같은 양식의 학습지

- 이번 주 “해저확장설 차시 학습지 만들어 줘” → 중1 과학 학습지 · 해저확장설
- 다음 주 “판의 경계 차시 학습지 만들어 줘” → 중1 과학 학습지 · 판의 경계
- 두 학습지는 같은 양식 (① 학습 목표 ② 핵심 개념 정리 ③ 그림 ④ 빈칸 채우기 ⑤ 서술형)
- **바뀐 것은 차시(Context) 한 줄, 양식(Skill)은 그대로.**

**발표자 노트**

> Skill을 저장해 두면 무엇이 좋은지 보여 드리겠습니다. 이번 주에는 '해저확장설 차시 학습지 만들어 줘', 다음 주에는 '판의 경계 차시 학습지 만들어 줘'라고만 요청했습니다. 바뀐 것은 차시라는 Context 한 줄뿐인데, 두 학습지는 학습 목표, 핵심 개념, 그림, 빈칸 5문항, 서술형 1문항이라는 똑같은 양식으로 나옵니다. 학생들은 매주 익숙한 양식으로 공부하고, 선생님은 양식을 매번 설명하지 않아도 됩니다. 이것이 Skill의 힘입니다.

### 28. 실습 2 · 방법 (Skill) 정하기 (7분)

1. **추천 규칙 누르기** — + 를 누르면 내 규칙에 추가
2. **나만의 규칙 1~2개 쓰기** — 예) 개념 → 그림 → 빈칸 → 서술형 순서
3. **자동 규칙 확인하기** — 상황에서 자동으로 생긴 규칙

- 다 됐는지 확인: ‘내 규칙’이 3개 이상이면 끝 (앱 권장: 3~7개)
- 오른쪽 이미지: 추천 규칙·내 규칙 화면(①②), 자동으로 추가된 규칙 화면(③)

**발표자 노트**

> 두 번째 실습입니다. '방법' 단계로 넘어가 주세요. 위쪽에 업무 유형에 맞는 추천 규칙이 보입니다. 마음에 드는 규칙을 누르면 내 규칙에 추가됩니다. 그리고 선생님이 평소 자료를 만들 때 지키는 나만의 원칙을 한두 개 직접 적어 보세요. 예를 들어 '핵심 개념 → 그림 1개 → 빈칸 5문항 → 서술형 1문항 순서로 만든다'처럼요. 화살표로 순서도 바꿀 수 있습니다. 아래쪽에는 앞에서 적은 상황, 즉 학년이나 오개념에서 자동으로 만들어진 규칙이 있습니다. 필요 없으면 체크를 풀면 됩니다. 약 7분 드리겠습니다.

## 04 하네스 (Harness)

### 29. Tool: AI의 손과 발

- **AI가 파일 · 검색 · 이미지 · 외부 서비스를 직접 쓸 수 있게 하는 능력**
- 방법(Skill)을 알아도, 파일을 열 수 없으면 일을 끝낼 수 없습니다.

| 연결하는 것 | 할 수 있는 일 (예) |
|---|---|
| Google Drive | 작년 PPT 찾아 읽기 |
| 웹 검색 | 최신 교육과정 확인 |
| 이미지 생성 | 판 경계 모식도 |
| Canva | 행사 포스터 초안 |
| Google Slides | 수업 슬라이드 작성 |
| 캘린더 | 행사 일정 확인 |

**발표자 노트**

> 스킬이 있어도 해결되지 않는 상황이 있습니다. '지난 학기 PPT 스타일을 참고해서 만들어 줘'라고 했는데 AI가 그 파일을 열어 볼 수 없다면, 아무리 좋은 방법을 알아도 소용이 없습니다. 레시피를 완벽히 알아도 부엌 열쇠가 없으면 요리를 못 하는 것과 같습니다. 그래서 AI가 파일을 열고, 검색하고, 그림을 그리고, 다른 서비스를 쓸 수 있게 해 주는 것이 툴(Tool)입니다. 서비스마다 플러그인, 커넥터, 앱 연결 등으로 부르는데, 스마트폰에 앱을 설치하면 할 수 있는 일이 늘어나는 것과 비슷합니다. 툴은 계정 연결과 권한 설정이 필요해서 오늘은 소개만 하고, 실습은 다음 기회에 하겠습니다.

### 30. 챗봇은 답을 주고, 에이전트는 일을 끝낸다

- 같은 부탁: “다음 주 현장체험학습 안내 가정통신문 준비해 줘.”

| 챗봇 | 에이전트 (Agent) |
|---|---|
| 가정통신문 글 한 편을 써 준다 | 1. 캘린더에서 일정 확인 |
| 날짜·장소는 비워 두거나 지어낼 수 있다 | 2. 드라이브에서 작년 양식 찾기 |
| 양식에 옮기고 확인하는 건 사람 몫 | 3. 학교 양식에 맞춰 작성 |
| | 4. 개인정보 포함 여부 점검 |
| | 5. 검토용 파일로 저장 |

**발표자 노트**

> 챗봇과 에이전트의 차이를 같은 부탁으로 비교해 보겠습니다. '다음 주 현장체험학습 안내 가정통신문 준비해 줘'라고 했을 때, 챗봇은 그럴듯한 가정통신문 글 한 편을 써 주고 끝납니다. 날짜와 장소는 비워 두거나 지어내기도 하죠. 에이전트는 캘린더에서 일정을 확인하고, 드라이브에서 작년 양식을 찾고, 학교 양식에 맞춰 작성하고, 개인정보가 들어가지 않았는지 점검한 뒤, 검토용 파일로 저장까지 해 줍니다. 심부름으로 비유하면 챗봇은 '두부 사 와'에 '두부는 마트에 있어요'라고 답해 주는 사람이고, 에이전트는 직접 가서 두부가 없으면 비슷한 걸 찾아보고 영수증까지 챙겨 오는 사람입니다.

### 31. Agent가 강력할수록, 환경과 검증이 더 중요하다

- 에이전트는 여러 단계를 혼자 진행합니다. 한 번 잘못 판단하면 그 실수가 다음 단계로 이어집니다.

| | 실수 | 예 |
|---|---|---|
| 01 | 잘못된 파일 선택 | 작년 교육과정 문서로 작성 |
| 02 | 근거 없는 사실 생성 | 존재하지 않는 연구 인용 |
| 03 | 잘못된 이미지 생성 | 해령 양쪽 나이가 비대칭 |
| 04 | 형식 불일치 | 학교 양식과 다른 공문 |
| 05 | 학생 개인정보 노출 | 실명·성적이 담긴 파일 공유 |
| 06 | 오개념 포함 | “맨틀이 녹아서 흐른다” |

**발표자 노트**

> 에이전트가 똑똑하면 다 해결될까요? 그렇지 않습니다. 에이전트는 스스로 여러 단계를 진행하기 때문에, 중간에 한 번 잘못 판단하면 그 실수가 다음 단계로 그대로 이어집니다. 잘못된 파일을 골라 작년 교육과정으로 자료를 만들 수도 있고, 근거 없는 사실을 지어낼 수도 있고, 과학적으로 틀린 그림을 만들 수도 있습니다. 학교에서는 특히 학생 개인정보가 노출되거나 학생에게 잘못된 개념이 전달되는 일은 반드시 막아야 합니다. 운전 실력이 좋은 자율주행차일수록 더 좋은 도로, 신호등, 안전장치가 필요한 것과 같습니다.

### 32. Harness Engineering (강조 장)

- **AI가 잘 일할 수 있는 환경을 설계한다.**

| 01 환경 설계 | 02 의도 명세 | 03 피드백 루프 |
|---|---|---|
| AI가 일할 자리와 재료를 갖춘다 | 무엇을 원하는지 분명히 적는다 | 결과를 검사하고 고치는 흐름을 만든다 |
| 예) 교육과정·학급 정보를 한 폴더에 | 예) “중1, 45분, 오개념 금지” | 예) 틀린 점을 규칙에 추가 |

**발표자 노트**

> 그래서 오늘의 핵심 개념, 하네스 엔지니어링이 나옵니다. 하네스(Harness)는 원래 말이나 썰매 개에게 채우는 마구, 또는 등산할 때 몸에 매는 안전벨트를 뜻합니다. 힘이 센 존재를 원하는 방향으로, 안전하게 움직이도록 연결해 주는 장치죠. AI도 마찬가지입니다. AI에게 '잘 시키는' 것이 아니라, AI가 잘 일할 수 있는 환경을 설계하는 것이 하네스 엔지니어링입니다. 구체적으로는 세 가지입니다. AI가 일할 자리와 재료를 갖추는 환경 설계, 원하는 것을 분명히 적는 의도 명세, 결과를 검사하고 고치는 흐름을 만드는 피드백 루프입니다.

### 33. 하네스는 여섯 가지로 이루어진다

|   | 구성 | 묻는 질문 | 학교에서는 |
|---|---|---|---|
| 1 | 상황 (Context) | 무엇을 알아야 하나 | 교육과정 · 학급 수준 |
| 2 | 방법 (Skill) | 어떻게 일하나 | 자료 제작 절차 |
| 3 | 도구 (Tool) | 무엇을 쓰나 | 드라이브 · 검색 |
| 4 | 작업 공간 | 어디서 일하나 | 나만의 비서 · 프로젝트 |
| 5 | 확인 기준 | 무엇을 통과해야 하나 | 사실 · 수준 · 개인정보 |
| 6 | 피드백 | 틀리면 어떻게 고치나 | 규칙 한 줄 추가 |

**발표자 노트**

> 하네스는 여섯 가지로 이루어집니다. 첫째 컨텍스트, AI가 알아야 할 정보입니다. 둘째 스킬, 일하는 방법입니다. 셋째 툴, 쓸 수 있는 도구입니다. 넷째 환경, 어디에서 일하는지입니다. SenGPT의 나만의 비서인지, ChatGPT 프로젝트인지, Claude Cowork인지 같은 작업 공간을 말합니다. 다섯째 퀄리티 게이트, 결과물이 통과해야 할 검사 기준입니다. 공항 검색대를 통과해야 비행기를 탈 수 있듯, 기준을 통과한 결과만 학생에게 갑니다. 여섯째 피드백, 실패했을 때 고치는 방법입니다. AI가 같은 실수를 하면 그 내용을 규칙에 추가해서 다음엔 안 틀리게 만드는 것입니다.

### 34. 하네스가 좋을수록, 요청은 오히려 짧아진다

| 짧은 요청 · 하네스 없음 | 긴 요청 · 하네스 없음 | 짧은 요청 · 하네스 있음 |
|---|---|---|
| 해저확장설 수업자료 만들어줘. | 매우 긴 프롬프트 (대상·목표·수준·주의사항…) | 해저확장설 자료 만들어줘. |
| 결과 △ | 결과 ○ | 결과 ◎ |

- 왜? 상황 · 방법 · 도구 · 확인 기준이 이미 환경에 저장되어 있기 때문

**발표자 노트**

> 재미있는 역설이 하나 있습니다. 하네스가 잘 갖춰질수록 사용자가 쓰는 프롬프트는 오히려 짧아집니다. 왼쪽처럼 맥락 없이 짧게 요청하면 결과는 그저 그렇습니다. 가운데처럼 매번 대상·목표·주의사항을 길게 쓰면 결과는 좋아지지만 매번 힘듭니다. 오른쪽은 똑같이 짧은 요청인데 결과가 가장 좋습니다. 필요한 정보와 방법, 도구, 검사 기준이 이미 환경 안에 저장되어 있기 때문입니다. 오래 손발을 맞춘 동료 선생님에게는 '그거 이번 주도 부탁해요' 한마디면 통하는 것과 같습니다.

### 35. 실습 3 · 확인 기준 정하기 (5분)

1. **꼭 필요한 기준 체크** — 내 업무에 필요한 3~5개
2. **확인 문장 다듬기** — ‘어떻게 확인할지’를 내 상황에 맞게
3. **‘완성 보기’ 누르기** — 도구는 필요한 것만 체크

- 다 됐는지 확인: 기준 3~5개를 체크하고 ‘완성 보기’ 화면이 열리면 끝
- 오른쪽 이미지: 확인 기준 체크 화면(①②), ‘완성 보기’ 버튼(③)

**발표자 노트**

> 세 번째 실습입니다. '확인 기준' 단계입니다. 결과물을 학생에게 주기 전에 꼭 확인해야 할 기준을 고르는 곳입니다. 업무 유형에 따라 몇 가지는 이미 체크되어 있고, 앞에서 오개념이나 참고자료를 적었다면 '자동 체크됨' 표시가 붙어 있습니다. 내 업무에 꼭 필요한 기준을 3~5개 체크하고, 오른쪽의 '어떻게 확인할지' 문장을 내 상황에 맞게 고쳐 보세요. 이 기준이 들어가면 AI가 결과를 내기 전에 스스로 점검하고, 마지막 확인은 선생님이 하시면 됩니다. 도구 단계는 필요한 것만 체크하고 '완성 보기'를 눌러 주세요. 약 5분 드리겠습니다.

### 36. 완성 · 결과 세 가지 복사하기

1. **바로 실행 프롬프트** — 지금 채팅창에 붙여 넣기
2. **AI 도구 지침 (하네스)** — 비서 · 프로젝트 지침 칸에 저장
3. **다음부터 쓸 짧은 요청** — ②를 저장한 뒤 한 줄로

- 복사하기 · .md로 내려받기 · 인쇄
- 공용 컴퓨터라면 마친 뒤 ‘처음부터 다시’
- 오른쪽 이미지: 완성 화면의 결과 탭 ①②③

**발표자 노트**

> 완성 화면입니다. 결과가 세 개의 탭으로 나옵니다. ① 바로 실행 프롬프트는 지금 AI 채팅창에 그대로 붙여 넣으면 바로 결과가 나오는 요청문입니다. ② AI 도구 지침은 SenGPT 나만의 비서나 ChatGPT·Claude 프로젝트의 지침 칸에 저장해 두고 계속 쓰는 설정문, 즉 오늘 만든 하네스입니다. ③ 다음부터 쓸 짧은 요청은 ②를 저장한 뒤에 쓰는 한 줄 요청 예시입니다. 각 탭에서 '복사하기'를 누르거나 '.md로 내려받기'로 파일로 저장해 가세요. 지금 바로 ①을 복사해서 평소 쓰시는 AI에 붙여 넣어 결과를 확인해 보셔도 좋습니다.

## 05 실제 도구

### 37. 한 번 쓸 일은 프롬프트로, 반복하는 일은 에이전트로

| | ① 프롬프트로 쓰기 | ② 에이전트로 만들기 |
|---|---|---|
| 1주 | 전체 프롬프트 다시 붙여 넣기 | 지침 저장 (한 번) + 짧은 요청 |
| 2주 | 전체 프롬프트 다시 붙여 넣기 | 짧은 요청 |
| 3주 | 전체 프롬프트 다시 붙여 넣기 | 짧은 요청 |
| | 새 대화창마다 처음부터, 고쳐도 그때뿐 | 늘 기억하고, 규칙 한 줄 추가로 계속 나아짐 |

**발표자 노트**

> 하네스 빌더의 결과 ①과 ②는 비슷해 보이지만 쓰는 방식이 완전히 다릅니다. ① 프롬프트는 채팅창에 한 번 붙여 넣고 쓰는 것입니다. 이번 일 한 번에는 충분하지만, 새 대화창을 열면 AI는 모든 걸 잊어버리고, 다음에 또 전체를 붙여 넣어야 합니다. 마음에 안 드는 점을 고쳐도 그때뿐입니다. ② 에이전트는 SenGPT 나만의 비서나 ChatGPT·Claude 프로젝트의 지침 칸에 하네스를 저장해 두는 것입니다. 그러면 AI가 상황·방법·기준을 늘 기억하고 있어서, 다음부터는 ③처럼 바뀌는 정보만 한 줄로 말하면 됩니다. 고칠 점이 생기면 지침에 규칙 한 줄을 추가하면 다음부터 계속 반영됩니다. 파일이나 검색 같은 도구를 켜면 자료를 찾아 쓰는 진짜 에이전트에 가까워집니다. 비유하면 프롬프트는 '대체 수업 메모 한 장', 에이전트는 '우리 학교 업무 매뉴얼을 익힌 전담 비서'입니다. 처음에는 ①로 한두 번 써 보고, 결과가 괜찮고 같은 일이 반복된다면 ②로 저장하는 것을 추천합니다.

### 38. 에이전트로 만들기 · 어디에 저장하나요?

| 도구 | ② 지침 붙여 넣기 | 참고 파일 (교과서 · 작년 자료) |
|---|---|---|
| SenGPT | ‘나만의 비서’ → 역할·지침 칸 | 참고 파일 |
| ChatGPT | 프로젝트 → 지침 | 프로젝트 파일 |
| Claude | 프로젝트 지침 또는 Skill | 프로젝트 파일 · 연결 폴더 |

- 한 번 넣어 두면, 다음부터는 “이번 주 학습지 만들어 줘” 한 줄이면 된다.

**발표자 노트**

> ② AI 도구 지침은 선생님들이 쓰시는 AI 도구 어디에든 넣을 수 있습니다. 이름만 다를 뿐 구조는 같습니다. SenGPT라면 '나만의 비서'를 만들어 역할·지침 칸에, ChatGPT라면 프로젝트를 만들어 지침에, Claude라면 프로젝트 지침이나 Skill로 저장합니다. 교과서 쪽수나 작년 자료 같은 참고 파일은 각각 참고 파일, 프로젝트 파일, 연결 폴더에 올리면 됩니다. 하네스 빌더 완성 화면 아래쪽에도 같은 표가 있습니다.

### 39. 시연 · SenGPT 나만의 비서에 넣어 보기

### 42. AI 시대의 교사 전문성

- AI가 강해질수록 교사의 전문성은 목표를 세우고, 판단하고, 검증하는 데 쓰인다.

| AI가 잘하는 것 | 교사가 해야 하는 것 |
|---|---|
| 생성 | 목표 설정 |
| 반복 | 맥락 판단 |
| 검색 | 교육적 판단 |
| 변환 | 오개념 판단 |
| 실행 | 검증 |

**발표자 노트**

> 마지막으로 꼭 드리고 싶은 말씀입니다. AI가 잘하는 것은 생성, 반복, 검색, 변환, 실행입니다. 빠르고 지치지 않죠. 하지만 무엇을 목표로 할지, 이 반 아이들에게 지금 무엇이 필요한지, 이 표현이 오개념을 부르지 않는지, 이 결과물을 정말 학생에게 줘도 되는지를 판단하는 것은 여전히 교사의 몫입니다. 오케스트라에 비유하면, 악기 연주는 점점 AI가 잘하게 되지만 어떤 곡을 어떤 해석으로 연주할지 정하는 지휘자는 교사입니다. AI가 강해질수록 교사의 전문성이 사라지는 것이 아니라, 그 전문성을 쓰는 방식이 바뀝니다.
