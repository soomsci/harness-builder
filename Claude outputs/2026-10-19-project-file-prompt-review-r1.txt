# 정적 리뷰 결과

치명적인 문제는 없습니다. 실제로 확인한 문제는 중간 2건, 낮음 2건입니다. `TEMPLATES.harness`의 시작 부분은 이번 자료에 없어서 직접 보지 못했습니다.

**중간 1. 기존 파일이 있을 때 처리 방법이 모호합니다 (기준 1·2)**
- 근거: setup 3번은 "다른 내용의 기존 지침은 덮어쓰지 마세요"와 "충돌 없는 새 원칙은 현재 대화에 적용"을 함께 씁니다. `CLAUDE.md`/`AGENTS.md`는 프로젝트 루트에 하나뿐입니다. 그래서 같은 프로젝트에서 두 번째 업무(예: PPT 다음 학습지)를 만들 때, AI가 파일에 쓰지 않고 대화에만 적용할 수 있습니다. 반대로 기존 파일을 고쳐 쓸 수도 있습니다.
- 최소 수정: 업무 제목 섹션을 기준으로 나눕니다. "같은 업무 섹션이 없으면 파일 끝에 섹션으로 추가하고, 있는데 내용이 다르면 기존 섹션을 유지하고 차이만 보고하세요."

**중간 2. 갱신 안내 문구 때문에 교사가 확정한 원칙이 사라질 수 있습니다 (기준 2·4)**
- 근거: 교사 수정은 AI 쪽 파일에만 들어가고 웹앱에는 반영되지 않습니다(루틴 5번). 그런데 안내 문구 "저장된 지침을 이번 내용으로 갱신해줘"를 그대로 따르면, 웹앱의 원문으로 파일을 덮어써 이미 편입된 수정 원칙이 지워집니다. 3번의 "보존" 지시와도 맞지 않습니다.
- 최소 수정: 문구를 "선생님이 확정한 수정 원칙은 유지하고, 이번 원문과 다른 부분만 갱신해줘"로 바꿉니다. 3번에는 "갱신할 때도 원문에 없는 교사 확정 원칙은 보존하고, 충돌하는 부분은 목록으로 보여 주세요"를 넣습니다.

**낮음 3. Grill 답변을 지침에 넣지 말라는 지시가 예외 없이 막습니다 (기준 4)**
- 근거: setup 6번은 "Grill에서 정한 답변은 지침에 옮기지 마세요"로 예외가 없습니다. 반면 루틴은 "앞으로/다음에도"라고 한 원칙을 편입하라고 합니다. 이전 문구의 "사용자가 별도로 요청한 경우"라는 예외가 이번에 빠졌습니다.
- 최소 수정: "지속 적용을 명시하고 확인받은 원칙은 '결과 수정 요구를 지침에 반영' 절차를 따르세요"라는 단서를 붙입니다.

**낮음 4. 루틴이 들어가는 위치가 불안정합니다**
- 근거: `harness.replace('\n\n', …)`는 harness 템플릿의 첫 빈 줄 위치에 따라 결과가 달라집니다. 루틴 첫 문장은 "아래 역할과 적용 범위"를 가리키는데, 템플릿 머리가 바뀌면 루틴이 본문 중간에 들어갈 수 있습니다. 여러 업무를 한 파일에 추가하면 `## 매 작업에서 지침 확인` 제목도 중복됩니다.
- 최소 수정: 테스트에 "루틴이 제목 줄 바로 다음, 첫 `## ` 앞에 있다"는 검사를 하나 추가합니다. 중복은 1번 수정(업무 섹션 기준)과 함께 "루틴이 이미 있으면 다시 넣지 않음"으로 처리합니다.

**문제 없음으로 판단한 항목**
- **이번 요청 정보 제외(기준 3):** 원문, 루틴 2번, setup 6번이 모두 이번 요청의 구체값을 막고, 테스트도 확인합니다.
- **Grill 대기(기준 5):** 답을 기다리는 동안 파일 저장과 제작을 금지합니다. 7번은 "위 질문 방식에 따라"로 제한되어 있습니다.
- **기존 기능 회귀(기준 6):** 스킬 출력(`outputs()[4]`)과 파일명은 그대로이고, 새 UI는 없습니다. 기존 점검을 다시 하라고 표시되지도 않고, 수정·재개·검토에 setup이 다시 들어가지도 않습니다.
- **과장 여부:** 일반 ChatGPT가 `AGENTS.md`를 자동으로 인식한다고 하지 않습니다. 파일 제공, 프로젝트 등록, 자동 적용 미확인을 구분해 둔 것도 적절합니다.

**결론:** 조건부 배포 가능입니다. 중간 2건은 `TEMPLATES` 안의 문구만 고치면 되니, 고친 뒤 `events.test.cjs`의 문구 검사를 갱신하고 배포하는 것을 권합니다. 지금 그대로 배포하면 같은 프로젝트에서 두 번째 자료를 만들거나 지침을 갱신할 때 교사 원칙이 사라질 위험이 남습니다.
