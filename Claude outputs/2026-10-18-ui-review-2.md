## 새로 찾은 P2

### P2-A. 기존 방법을 교체하면, 다음 고칠 점의 적용 시점이 '다음에도 쓰기'로 남음
- **원인:** `updateFixScope()`가 교체를 고르면 `state.drafts.fixScope='always'`를 저장합니다. 그런데 교체 선택을 다시 풀 때 원래 값으로 되돌리지 않습니다. 이 값은 `addFix()`와 새로고침 뒤에도 남습니다(`applyFixes()`만 'request'로 되돌림).
- **재현:**
  1. 고치기 단계에서 '기존 방법을 바꾸나요?'로 규칙 하나를 고르고 담습니다.
  2. 두 번째 고칠 점을 '새 방법으로 추가'로 적습니다. 적용 시점이 '다음에도 쓰기'로 미리 선택돼 있습니다.
  3. 그대로 반영하면, 이번에만 고치려던 내용이 기본 설정과 SKILL.md에 들어갑니다.
  - 교체할 규칙을 골랐다가 다시 '새 방법으로 추가'로 바꿔도 똑같습니다.
- **최소 수정안:** 강제로 바꾼 값은 초안에 저장하지 않습니다.
  ```js
  scope.disabled=!!replace.value;
  scope.value=replace.value?'always':(state.drafts.fixScope||'request');
  ```
  위 두 줄로 바꾸고, `state.drafts.fixScope='always'` 줄은 지웁니다.

### P2-B. (P2-3에서 남은 문제) 보호 중인 원본을 예시 불러오기나 새로 만들기가 덮어씀
- **원인:** 예시 불러오기 처리는 `loadIssue=''`로 비운 뒤 `save()`를 부릅니다. 이때 확인 창 문구는 "지금 입력한 내용을 예시로 바꿀까요?"뿐입니다. `resetAll`(배너의 '새로 만들기'도 포함)도 일반 문구로 확인한 뒤 덮어씁니다.
- **재현:** 저장 데이터가 손상된 상태로 페이지를 엽니다. '이전 저장 내용 보관하기'를 누르지 않고 예시·도움말에서 수업 예시를 불러온 뒤 확인을 누릅니다. 그러면 원본이 영구히 사라집니다.
- **최소 수정안:** `load()`의 `catch`에 아래 한 줄을 넣으면 모든 경로가 막힙니다.
  ```js
  try{if(unreadableSavedData)localStorage.setItem(KEY+'-broken',unreadableSavedData)}catch{}
  ```

## P3 — 다듬을 점

| 근거 | 최소 수정안 |
|---|---|
| `<option value="${state.ruleIds[i]}">`에서 저장소에서 읽은 ID를 `esc` 없이 넣음 (같은 출처에서만 생길 수 있음) | `esc()`를 씌우거나, `syncRules`에서 ID가 `/^r[a-z0-9]+$/` 모양이 아니면 새로 만듦 |
| 옛 데이터의 고칠 점이 `replace`를 쓰면서 범위는 'request'임. 반영하면 거절 안내만 나와서 지우고 다시 담아야 함 | migration에서 `if(f.replace)f.scope='always'` |
| 하네스 작업 순서 3·4의 "선택한 결과 확인 기준으로 점검…" 문장이 확인 기준이 0개여도 남음 (실행 요청문 쪽은 해결됨) | 실행 요청문처럼 "선택한 확인 기준이 있으면…" 조건 문장으로 바꿈 |
| `undo-fix`가 반영한 뒤에 입력한 `drafts`·`check`까지 반영 전 값으로 덮음. 예: 반영 → 2단계에서 새 방법 초안 입력 → 되돌리기 → 그 초안이 사라짐 | 되돌릴 때 `drafts`는 지금 값을 유지하거나, 초안을 입력하면 `undoFix=null` |
| 라디오를 화살표 키로 움직여 묶음 경계(시각자료 → 가정통신문)를 넘으면 확인 창이 뜸 | 확인 창이 있어서 데이터는 안전함. 그대로 둬도 됨 |
| `getItem` 자체가 막힌 경우에도 "보호하고 있어요"라고 안내함 | 이전 지적과 같음. 문구를 구분 |

## 문제를 찾지 못한 경로
- **규칙 ID 짝 맞추기:** 위·아래 이동, 삭제, 칩 해제, 되돌리기에서 `skills`와 `ruleIds`가 항상 함께 바뀝니다.
- **다시 그리기:** textarea의 `change` 이벤트는 render하지 않고 끝나므로, 한글 입력과 포커스는 그대로입니다.
- **새 요청 기능:** 재사용 출력 세 가지(인덱스 1, 2, 4)에 이번 차시·목표·오개념이 섞이지 않습니다.
- **빈 항목:** 결과 확인 기준과 도구가 비어 있으면 해당 문단이 통째로 빠집니다.
- **스킬 파일:** 이름이 `teacher-{type}`이고, 도움말·복사 안내 문구도 같은 이름으로 바뀝니다.
