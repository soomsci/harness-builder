## 해결 확인 (R2 오독 정정 포함)
- **분량 드롭다운은 있습니다.** 수업형은 `field(out)`가 `choiceInput`(선택지 + 직접 입력)으로 그려지고, 위치도 `extra-context`보다 앞입니다. 문서형 `decided`도 앞으로 왔습니다. 다만 문서형 `form`은 여전히 두 번 접힌 안에 있으니, 의도한 배치인지 확인해 주세요.
- **등록 후 판정 칸은 펼쳐집니다.** `render('feedback-checks')`가 그 칸을 강제로 펼치고, 이후 렌더링도 `!needsRecheck()`이면 펼칩니다. 다시 점검이 필요할 때는 버튼이 접힌 영역 밖에 있습니다.
- **6단계 재접속은 됩니다.** `load`가 step 6을 허용하고, 실행 모드 5단계에 'AI 결과를 받았어요'가 항상 있습니다.
- 7개 항목 모두 반영을 확인했습니다: file 도구 제거, 복사 우선, 재사용 접기, 빈 미리보기와 `transferIssue` 자료 유형 검사, 날짜 표시와 ISO 보존, 검색 안내.

## 남은 문제와 최소 수정

1. **[중] 절차 버전만 달라도 허위 안내가 나갑니다.**
   - 원인: 입력값이 같고 절차 버전만 다르면 `conditionDifference`가 `'app'`을 돌려줍니다.
   - 영향: file 도구를 쓰지 않은 기존 사용자도 요청문 내용이 완전히 같은데, 검토·이어하기 요청문(L651)에 "기존 결과가 이 조건으로 만들어졌다고 가정하지 마세요… 새 조건이 추가되었습니다"가 들어갑니다.
   - 수정: 스냅샷에 절차·도구 블록이 이미 들어 있으므로 L669를 아래처럼 바꾸면, 문장이 실제로 바뀐 사용자(file 선택)만 다시 확인합니다.
     `return a.procedureVersion===b.procedureVersion||JSON.stringify(a.blocks)===JSON.stringify(b.blocks)?'same':'app';`
   - 전원 재확인을 유지하려면, 최소한 바뀐 블록이 없을 때 문구를 "교사 입력은 같고 앱의 확인 절차만 갱신됨"으로 바꿔 주세요.
   - 새 테스트의 `old.procedureVersion=1` 단언은 file을 포함한 상태로 고쳐야 합니다.

2. **[중] 2차 결과가 1차 이름으로 등록됩니다.**
   - 원인: 1차 등록 뒤 `resultName`에 "…·1차"가 남고, 이름 제안은 빈칸일 때만 채워집니다.
   - 영향: 이름을 고치지 않고 '새 결과로 등록'을 누르면 "2차 결과 · …·1차"로 기록되어 근거가 뒤섞입니다.
   - 수정: `new-result` 첫 조건을 아래처럼 바꿉니다.
     `if(!state.resultName?.trim()||state.resultRecord&&state.resultName.trim()===state.resultRecord.name)state.resultName=suggestedResultName();`

3. **[하~중] 처음 제안한 이름이 굳어집니다.**
   - 원인: `go(6)`이 제안을 placeholder가 아니라 실제 값으로 저장합니다.
   - 영향: 그 뒤 주제나 자료를 바꿔도 이름이 갱신되지 않아, 옛 주제 이름으로 등록될 수 있습니다.
   - 수정: placeholder와 `new-result`의 대체값이 이미 있으므로 L1084를 지우는 것이 가장 작습니다(테스트 기대값도 바꿔야 함). 꼭 값으로 보여야 한다면 자동 제안값을 따로 저장하고, 사용자가 고치지 않았을 때만 갱신하세요.

4. **[하] file 도구의 의미가 일부 사용자에게서 사라집니다.**
   - 영향: 문서형이고 출처가 비어 있으면 자료 제공 방식이 'none'이 되어, 예전 '첨부 파일 참고' 지시가 조용히 빠집니다. 'file' 값은 화면에서 해제할 수도 없는 채로 남습니다.
   - 수정: `load`에 `if(s.tools.includes('file')&&!s.ctx.textbookMode)s.ctx.textbookMode='attach';`를 넣습니다.

5. **[하] 참고자료 안내끼리 어긋납니다.**
   - `referenceView` 첫 안내 "파일은 AI 채팅에 직접 첨부해요"가 발췌·없음 모드에도 보입니다. 발췌 모드 요청문은 '원본 첨부를 전제하지 말라'고 하므로, `mode==='attach'`일 때만 보이게 하세요.
   - 참고자료 없음 + 결과 첨부일 때 "참고자료 없이… 결과 파일도"가 됩니다. "파일은"으로 바꾸세요.

6. **[하·접근성] 모드 전환 뒤 포커스가 사라집니다.** `render(mode.id,false)` 후에는 그 id가 화면에 없습니다. `render('pageTitle',false)`로 바꾸세요.

7. **[하] 빈 점검 기록이 쌓입니다.** 등록 직후 조건이 바뀌어 다시 점검하면, 판정·근거가 비어 있는 기록이 이력에 남습니다. `archiveCheck`에서 둘 다 비었으면 이력에 넣지 않으면 됩니다.
