# 하네스 빌더 개선본 검토 결과

받은 소스만 읽고 검토했습니다. 코드는 고치지 않았고, 자체 점검과 브라우저 실행도 하지 않았습니다.

**요약:** 실행 오류는 찾지 못했습니다. 다만 초보자가 자주 지나갈 경로에서 입력이나 규칙이 사라지는 문제가 2건 있습니다(P1). 재사용 설정이 다른 내용과 섞이거나 저장된 데이터가 덮어써지는 문제도 3건 있습니다(P2).

---

## P1 — 데이터 유실·초보자 막힘

### P1-1. 자료 종류를 처음 고를 때 이미 적은 입력이 전부 지워짐
- **코드 근거:** `changeType()`은 `hasInput()`이 참이면 확인 창을 띄우고 `state={...blank(),step,type,...}`로 상태를 통째로 비웁니다. 그런데 `hasInput()`은 `state.type`이 비어 있어도 `task`나 `ctx`가 있으면 참입니다.
- **재현 1:** 첫 방문에서 종류를 고르지 않고 '상황 알려주기'를 누릅니다(화면에 "빈칸이 있어도 다음으로 갈 수 있어요"라고 나옴). 학년·차시·목표를 적습니다. 방법 단계에 추천 방법이 없어서 업무 단계로 돌아가 '학습지'를 고릅니다. "자료 종류를 바꾸면… 비워져요" 창에서 확인을 누르면 상황 입력이 모두 사라집니다. 취소하면 종류를 아예 고를 수 없어서 막힙니다.
- **재현 2:** '하고 싶은 일'을 먼저 적고 종류를 골라도 똑같이 지워집니다.
- **함께 생기는 문제(P2 수준):**
  - '직접 입력'을 고른 직후 '업무 문서'를 누르면, 아무것도 적지 않았는데도 확인 창이 뜹니다. `hasInput()`이 `state.type`을 입력으로 세기 때문입니다.
  - 같은 묶음 안에서 종류를 바꿔도(PPT → 학습지) 칸 구성은 같은데 상황 입력이 지워집니다.
  - 키보드로 라디오 사이를 화살표로 움직이면 한 칸마다 `change`가 일어나서, 확인 창이 계속 뜨고 확인할 때마다 지워집니다.
- **최소 수정안:**
  ```js
  function changeType(type,nextGroup){
   const g=nextGroup||PRESETS[type].group||state.group;
   if(state.type===type&&state.group===g)return true;
   if(!state.type||group()===g){state.type=type;state.group=g;return true;} // 입력 유지
   const typed=state.task||state.skills.length||state.log.length||Object.values(state.ctx).some(Boolean);
   if(typed&&!confirm(...))return false;
   ...기존 초기화
  }
  ```

### P1-2. '기존 방법 교체'를 기본값 '이번에만'으로 반영하면 원래 규칙이 기본 설정에서 영구히 사라짐
- **코드 근거:** `applyFixes()`는 `f.replace`가 있으면 범위와 상관없이 기존 규칙을 `splice`로 지웁니다. 새 규칙은 `ruleScope='request'`라서 재사용 출력에도 들어가지 않습니다. 기록에는 새 문장만 남고(`수정 · 이번만: 새문장`) 원래 문장은 남지 않습니다. `undoFix`는 다음 편집이나 새로고침 한 번이면 없어집니다.
- **재현:** 수업 예시를 불러옵니다. 사용하기 → 결과 확인하고 고치기로 갑니다. 고칠 방법을 적고 '기존 방법을 바꾸나요?'에서 '교과서 용어를 그대로 쓴다'를 고릅니다. 적용 시점은 기본값('이번에만 쓰기') 그대로 두고 반영합니다. 그러면 '계속 쓸 기본 설정'과 SKILL.md에 원래 규칙도 새 규칙도 없습니다.
- **최소 수정안:** `addFix()`에서 교체를 고르면 범위를 `'always'`로 고정하고 "기존 방법 교체는 다음에도 적용돼요"라는 안내를 보여 줍니다. 기록에는 `수정: 원래문장 → 새문장`처럼 원래 문장도 남깁니다.

## P2 — 출력 오염·저장 보존

### P2-1. '이번에만' 항목이 다음 요청에도 계속 남음 (피드백 누적 문제가 그대로임)
- **코드 근거:** 범위가 request인 규칙, `qgText`(기본값이 이번에만), `check`가 모두 `state`에 계속 남습니다. `skillList(v)`와 `gateText(q,v)`가 이것들을 실행 요청문과 검토문에 계속 넣습니다. 이것들만 지우는 방법은 없고, '새로 만들기'를 누르면 고정 상황·기록까지 한꺼번에 지워집니다.
- **재현:** v2에서 '이번에만' 규칙을 반영합니다. 다음 주 수업 준비로 이번 차시와 목표만 바꿉니다. 그러면 '지금 사용할 요청문'과 '결과 검토 요청문'에 지난주 '이번에만' 규칙과 고친 확인 문장이 그대로 들어 있습니다. 버전이 올라갈수록 이런 항목이 쌓입니다.
- **최소 수정안:** 결과 화면에 "같은 기본 설정으로 새 요청" 버튼을 하나 둡니다.
  ```js
  state.skills=state.skills.filter(t=>scopeOf(t)==='always');
  for(const f of fieldsNow())if(!isFixed(f))delete state.ctx[f.k];
  for(const k in state.qgText)if(state.qgScope[k]!=='always')delete state.qgText[k];
  state.task='';state.check={};state.fixes=[];
  ```

### P2-2. 규칙 끝에 공백이나 줄바꿈이 있으면, 새로고침 뒤 '이번에만' 규칙이 기본 설정과 SKILL.md에 들어감
- **코드 근거:** `renameRule()`은 `t.value`를 다듬지 않고 그대로 키로 씁니다(`ruleScope["문장\n"]`). 그런데 `load()`는 `s.skills`만 `trim()`하고 `ruleScope` 키는 그대로 둡니다. 그래서 `scopeOf(문장)`이 `undefined`가 되고, 결과적으로 `'always'`로 처리됩니다.
- **재현:** '이번 수업은 그림 8개'를 '이번에만'으로 추가합니다. 다듬기 칸에서 문장 끝에 Enter를 누른 뒤 새로고침합니다. 범위가 '다음에도 쓰기'로 바뀌어 있고, 이 규칙이 기본 설정과 스킬 파일에 들어갑니다.
- **최소 수정안:** `load()`에서 다듬을 때 키도 같이 옮깁니다.
  ```js
  s.skills=s.skills.map(t=>{const n=t.trim();if(n!==t&&t in s.ruleScope&&!(n in s.ruleScope)){s.ruleScope[n]=s.ruleScope[t];delete s.ruleScope[t];}return n;}).filter(Boolean);
  ```
- **같은 원인의 드문 경우(P3):** 문장을 키로 쓰기 때문에, 고치는 도중 한순간이라도 다른 규칙과 문장이 같아지면 `delete state.ruleScope[old]`가 그 다른 규칙의 범위까지 지웁니다.

### P2-3. 저장 데이터를 읽지 못하면, 첫 입력 때 원본을 백업 없이 덮어씀
- **코드 근거:** `load()`의 `catch`는 `blank()`를 돌려줍니다. 그다음 `save()`가 한 번만 불려도 같은 키(`KEY`)의 원본이 사라집니다. 화면에는 "원본이 있는지 확인해 주세요"라고 나오지만, 원본을 확인할 방법이 없습니다.
- **원인이 더 생기는 경우:** `Object.hasOwn`이 없는 오래된 브라우저(Safari 15.4 미만, Chrome 93 미만)에서는 `load()` 안에서 TypeError가 나서, 멀쩡한 데이터도 손상된 것으로 처리됩니다.
- **최소 수정안:**
  - `catch` 안에서 `localStorage.setItem(KEY+'-broken', raw)`로 원본을 따로 보관합니다.
  - `Object.hasOwn(o,k)`는 `Object.prototype.hasOwnProperty.call(o,k)`로 바꿉니다.
  - `localStorage` 접근 자체가 막힌 경우(오류가 `getItem`에서 남)는 "읽지 못했어요"와 다른 문구로 구분합니다.

## 문제를 찾지 못한 항목
- **입력 중 다시 그리기:** `input` 이벤트에서는 `save()`와 `live()`만 하고 화면을 다시 그리지 않습니다. 그래서 한글 입력이 끊기거나 포커스를 잃는 문제는 없습니다. `change` 때 다시 그려도 열린 상세 영역, 입력 중인 글, 포커스가 되살아납니다.
- **화면에 넣는 값:** 모두 `esc()`를 거치므로 화면에 HTML이 끼어드는 경로를 찾지 못했습니다.
- **재사용 출력:** 이번 차시·목표·오개념이 기본 설정, 요청 양식, SKILL.md에 기본값으로 섞이지 않습니다. 위 P2-2와 P3 예외만 있습니다.
- **SKILL.md 앞부분:** `description`을 `JSON.stringify`로 만들어 올바른 YAML 문자열이 됩니다.

## 확인하지 못한 점
- **v1.2에서 넘어오는 데이터:** v1.2의 저장 모양을 비교하지 못했습니다. 만약 v1.2에서 고친 규칙이 `skills`가 아니라 `log`에만 있었고 출력이 `log`에서 규칙을 만들었다면, 이번 버전에서는 그 규칙들이 조용히 빠집니다. 이 경우는 **P1**입니다. 자체 점검 이름 "기록에서 되살아나지 않음"을 보면 그럴 가능성이 있습니다. `git show HEAD:index.html`에서 `fixed`, `log`, `qgText`의 모양을 확인해 주세요. 저장 형식에 버전 필드(`schema`)를 넣어 두면 옛 데이터를 옮기는 분기를 만들기 쉽습니다.
- **직접 실행하지 않은 것:** 자체 점검 56개는 돌려 보지 않았습니다. 아래 항목도 실제로 확인하지 못했습니다.
  - iOS Safari에서 대체 복사(`execCommand`)가 되는지
  - Firefox·Safari에서 DOM에 붙이지 않은 `a.click()`으로 내려받기가 되는지
  - 인쇄 때 뒤에 빈 쪽이 생기는지
  - 모바일 키보드가 열렸을 때 아래 고정 막대가 어떻게 보이는지
  - 화면 읽기 프로그램이 실제로 어떻게 읽는지
- **자체 점검에 추가할 것:** `changeType`이 입력을 유지하는지, `load`의 trim과 범위가 맞는지, 교체+이번에만 조합. 이 세 가지를 넣으면 위 P1·P2의 재발을 막을 수 있습니다.

## 기능 확장 제안 (3개)
1. **설정 JSON 내보내기/불러오기:** 기기를 바꾸거나 공용 PC를 쓸 때 백업할 수 있습니다. 서버가 필요 없습니다.
2. **기본 설정 붙여 넣을 곳 한 줄 안내:** ChatGPT 프로젝트, Gemini Gem, Claude 프로젝트별로 어디에 붙여 넣는지 알려 줍니다.
3. **업무 설정 여러 개 저장:** 명세 9절의 다음 버전 후보입니다. 스킬 이름이 겹치는 문제(P3)와 함께 해결됩니다.
