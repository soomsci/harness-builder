# 컨텍스트 관리 개편 계획 — Claude 검토 입력

## 목적과 판단 우선순위

대상은 AI와 기술 용어에 익숙하지 않은 교사다. 사용자는 정보가 한꺼번에 많이 보이면 거부감이 생긴다고 명시했다.
핵심 목적은 교사가 적은 입력으로 필요한 맥락을 AI에 전달하고, PPT·학습지·HTML 웹앱 등 실제 결과를 검토·수정하며, 다음 작업이나 새 대화에서도 필요한 정보를 이어 쓰도록 돕는 것이다.
‘하네스’나 ‘컨텍스트 엔지니어링’이라는 이름을 붙이기 위한 기능 확대가 목적이 아니다. 요청문 문구만 늘리는 대신 실제 정보 선택·적용 범위·작업 상태·근거를 관리해야 한다.
우선순위: (1) 초보자의 작업 성공과 낮은 입력·왕복 부담 (2) 맥락의 정확성·기존 데이터 보존 (3) 결과 검토와 재개 가능성 (4) 유지보수 가능한 구현 (5) 용어·포장.
성공 여부는 사용자가 실제로 필요한 자료를 만들고 고쳐 이어갈 수 있는지로 판단한다. 자동 실행을 하지 않는 제품을 실행 하네스라고 주장하지 않는다. 결과물 품질 향상은 비교 평가 전에는 미검증이다.

## 사용자 요청과 이번 검토 범위

사용자는 위 목적을 반영한 계획을 요청한 뒤, 이 계획을 Claude에게 검토받되 목적을 먼저 설명하고 그 목적 아래에서 검토하라고 요청했다.
이번 작업은 계획 검토뿐이다. 구현·배포·로그인·파일 수정·외부 서비스 조작을 하지 말 것. 아래 계획을 기정사실로 승인하지 말고 필요하면 축소·재순서화하라.

## 현재 제품과 제약

단일 index.html, 내장 JS/CSS, 서버·AI API·로그인 없음. 입력은 localStorage에 보관. 기존 schema 3은 단일 작업의 type/task/ctx/skills/ruleIds/ruleScope/fixed/qg/check/fixes/log/drafts를 보관한다.
기본 UI는 5단계(업무→상황→방법→확인→사용하기), 피드백 별도. 기본 상황 질문 3개, 상세 옵션 접힘.
자료 종류는 HTML 기반 웹앱(맨 앞), PPT, 학습지, 평가문항, 학생용 설명자료, 시각자료, 가정통신문, 업무 문서, 직접 입력.
출력은 실행 요청, 재사용 지침, 다음 요청 양식, 검토 요청, SKILL.md. 현재 도구 선택·검토 기준은 지시문 생성이며 실제 도구 연결/검사 실행이 아님.
현재 추천 방법은 사용자가 선택한 것만 반영. 같은 그룹에서 자료 종류 변경 시 상황은 유지하고 규칙·검토 등은 초기화하므로 여러 자료를 동시에 보관하지 못한다.
기존 저장 복구·탭 충돌·클립보드 실패 처리가 있으며 이를 퇴행시키면 안 된다. 실제 테스트는 자체 70개 및 별도 상태/출력 회귀 검사가 있다. 검사 통과가 결과물 품질 또는 전체 브라우저 시각 검수 통과를 의미하지 않는다.
외부 API 없이 사람의 복사·붙여넣기로 맥락을 전달하는 1차 버전과, 외부 에이전트 실행 환경 연동 후속 단계를 구분한다. 기존 단일 HTML 제약과 저장소 용량이 계획과 충돌하면 숨기지 말고 선택지와 최소 권고안을 적어라.

## 검토할 계획

1. 수업과 제작 자료 분리 저장
- 기본 설정: 학년·교과·학급 특성·반복 원칙.
- 수업/업무: 목표·차시·확정 사항·참고자료.
- 제작 자료: 종류·분량·제작 방법·완료 기준.
- 결과 버전: 결과물·점검·수정·남은 문제.
- 한 수업 아래 PPT·학습지·웹앱을 보관. 가정통신문/업무 문서는 별도 업무.
- 기존 데이터는 ‘기존 작업’으로 이전, 원본 보존, 실패 시 덮어쓰기 금지.
- 완료 기준: 자료 전환 시 각 분량·방법·결과 유지, 새 수업에 지난 차시가 따라오지 않음.

2. 자료별 입력과 추천 방법
- 웹앱: 학생 활동·조작 시 변화·사용 기기. PPT: 흐름·장수·참여 활동. 학습지: 활동/문항·쪽수·정답 분리. 평가: 평가 내용·문항 수·난이도.
- 추천 방법 기본 적용, 접힌 ‘방법 바꾸기’에서 수정/해제. 다른 자료의 조건 이월 방지.
- 완료 기준: 동일 수업이면 목표는 공유하되 제작 요구·확인 기준은 종류별로 다름.

3. 참고자료 실제 내용 관리
- 1차는 텍스트 붙여넣기와 출처 기록. 이름·본문·출처/쪽수·적용 수업 저장.
- 이번 작업에 필요한 자료만 선택해 포함. 이름/링크만 있는 자료는 AI에 별도 전달 필요 표시.
- 긴 자료는 발췌 선택. 임의 잘라내기 또는 읽었다는 표시 금지.
- 요청에 담긴 정보를 짧게 요약하고 상세는 접기. PDF/PPT 자동 추출·의미 검색은 후속.
- 완료 기준: 포함한 근거 확인 가능, 다른 수업 자료가 섞이지 않음.

4. 제작·검토·수정·이어 하기별 맥락 조합
- 제작: 목표+요구+참고자료+방법.
- 검토: 실제 결과물+요구+기준+근거.
- 수정: 최신 결과물+발견 문제+유지 사항.
- 이어 하기: 확정 사항+최신 결과+미해결 문제+다음 행동.
- 텍스트·HTML 코드 입력 지원. PPT/PDF는 첨부 안내와 버전 정보만 관리, 본문을 읽었다고 취급하지 않음.
- 완료 기준: 결과물 없이 검토 완료 표시 불가, 최신 결과 기준 수정 요청 생성.

5. 점검·피드백·기억을 작업 상태에 연결
- 결과(미확인/통과/수정 필요/확인 불가)와 근거(AI 보고/교사 확인/실행 검사 결과) 구분.
- 결과물 버전별 기록, 새 버전은 다시 확인. 이전 검사는 이력으로 보존.
- 피드백은 기본 이번 자료에 적용. 다음에도 적용은 명시적 선택, 유형별 원칙 범위 관리.
- 완료 기준: 이전 통과가 새 버전에 자동 승계되지 않음, 일회성 수정이 영구 규칙이 되지 않음.

6. 초보자 UI와 검증
- 기본 행동: 만들 자료 정하기 → AI에 전달하기 → 결과 가져와 고치기.
- 첫 화면에는 자료 종류와 핵심 질문 약 3개. 참고자료·세부 방법·버전·스킬 파일은 접기.
- 같은 수업으로 다른 자료 만들기 제공.
- 검증 시나리오: 동일 수업 3종 자료, 결과 검토/수정, 새 대화 재개, 다음 수업 분리, 저장 마이그레이션/실패/탭 충돌, 모바일/키보드.
- 기존 검사에 추가, 데스크톱·모바일·내보내기 실기 검수, Claude 코드 검토 반영.
- 제시한 개발 순서는 1→2→3→4→5→6. 중간 구조 변경본을 공개하지 않고 전체 흐름 검증 후 배포, 공개본 일치와 내부 파일 비공개 확인.

후속: 기존 외부 에이전트 실행 환경과 파일 전달·실행 결과 수집·재시도·작업 재개 연동. 1차 범위에는 API 키·자동 실행·자동 검증이 없음.

## 요청하는 검토 형식

한국어로 아래 순서로 답하라. 형식적인 칭찬보다 구체적 근거와 고칠 내용을 우선한다.
1. 목적 기준 전체 판정: 이 계획이 초보자의 실제 작업을 개선하는가? 구현 전 해결해야 할 문제가 있는가?
2. 우선순위별 발견 사항 표: 심각도(P0/P1/P2), 계획 항목, 실패하는 구체 사용자 상황, 목적에 미치는 영향, 최소 수정안. 확인된 사실/추론을 구분한다.
3. 원안에서 유지/변경/삭제/후속으로 미룰 항목. 추천 기능을 무조건 추가하지 말고 제거할 부담도 검토한다.
4. ‘컨텍스트 엔지니어링’의 실질: 현재보다 무엇을 실제로 선택/갱신/전달하는가? 입력 폼과 긴 프롬프트를 늘리는 데 그치지 않는가? 실제 전달을 관측할 수 없는 경계는?
5. 초보자 여정 검토: 첫 웹앱 생성, 같은 수업 학습지 추가, AI 결과 가져오기·수정, 새 채팅 재개. 각 경우 사용자가 해야 하는 행동과 반드시 줄일 마찰.
6. 권장 최소 첫 배포 범위와 개발 순서. UI 검증을 마지막으로 미룬 순서가 적절한지 검토한다. 한 번의 완결된 왕복 시나리오로 가치 검증하는 방안도 제시한다.
7. 관찰 가능한 완료 기준/시험 사례(정상·실패 포함)와 사용자 효용 평가. 수치나 성능 향상을 근거 없이 주장하지 말 것.
8. 구현 전 확정해야 할 결정 중 설계자가 기본값을 정할 수 있는 것과 사용자에게 꼭 물어야 하는 것을 구분. 불필요한 사용자 질문을 늘리지 말 것.

특별히 확인할 위험: 기존 데이터의 범위 모호성/손실, 공유 맥락 수정 후 기존 결과·검토의 유효성, 결과 버전과 요청 당시 맥락의 연결, 외부 파일 실제 첨부 여부, 일반 채팅에서 기억/파일 자동 접근 가정, localStorage 용량과 결과물 버전 증가, 공용 PC의 원본·백업 삭제 범위, 상충하는 공통/유형/이번 요청 원칙, 복붙 횟수와 잘못된 버전 선택, 근거 없는 검증 통과, 기존 사용자의 추천 규칙 자동 변경.
