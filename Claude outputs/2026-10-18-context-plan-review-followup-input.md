계획 검토 후속 요청. 한국어로 1,500자 이내로 답하라. 읽기 전용, 도구 사용·코드 변경 없음. 실행·사용성 검증을 했다고 주장하지 말 것.

사용자의 최신 요구: “아 근데 그래도 프롬프트 엔지니어링과는 차별화된걸 꼭 눈에 띄게 하고싶어”.
이것은 원래 목적(초보 교사가 적은 입력으로 필요한 맥락을 전달하고 결과를 검토·수정·재개하는 것)에 추가된 필수 제품 기준이다. 용어만 바꾸거나 프롬프트 길이를 늘리는 과장이 아니라 실제로 차이를 체감하고 볼 수 있어야 한다. 프롬프트 엔지니어링과 컨텍스트 엔지니어링은 겹치므로 완전히 별개 기술이라고 포장하지 않는다. 현재 앱은 단일 HTML/localStorage/AI API 없음. 기존 UI 5단계, 현재 상태는 한 작업. 신규 기능은 아직 구현하지 않았다.

총괄의 수정안:
- 첫 배포에도 수업→자료의 구분과 자료 전환 보존, 유형별 분량/방법 분리를 포함한다.
- 결과 화면의 긴 설명 대신 ‘이번에 AI에 보낼 정보’ 한 줄 요약을 둔다. 예: ‘수업 정보 + 학습지 방법 + 참고 내용 1개’. ‘포함/제외 이유’ 상세는 접어 둔다. AI가 실제 수신·읽었다는 상태로 표시하지 않는다. 글자 수를 품질 점수로 쓰지 않는다.
- 같은 수업 웹앱→학습지 전환 시 ‘학습목표 유지 · 웹앱 조작 조건 제외 · 학습지 형식 적용’을 짧게 보여준다. 실제 조합 결과에서 검증 가능한 변화여야 한다.
- 참고자료는 첫 배포에 본문 발췌 1개와 출처를 포함한다. 여러 자료 검색·파일 자동 추출은 후속. 이름/링크만 있으면 전달 대기이고 ‘읽음’으로 표시 금지.
- ‘고치기’의 기본은 같은 채팅용 문제+유지할 내용만 복사. 새 채팅용은 확정 내용+최신 결과 또는 첨부 안내+남은 문제로 자립 가능한 전달문을 조합한다. 같은 채팅에도 모든 결과가 남아 있다고 보장하지 않는다.
- 요청 당시 맥락 스냅샷과 결과의 연결은 교사가 확인한다. 수업 목표/자료 내용/요구사항이 바뀌면 과거 점검에 즉시 ‘이전 조건에서 확인’ 표시. 해시만 저장하면 당시 상태 복원 못하므로 최소한의 실제 조건과 버전을 함께 보존한다. 이 기능은 첫 배포 필수.
- 결과 저장은 선택, 텍스트 크기 제한과 최신/직전만 보관, 작은 상태 저장과 분리. 저장 실패 시 일부만 성공한 상태를 완전 저장으로 표시하지 않는다. 새 키 마이그레이션·삭제 범위·복구본·다중 탭 보호는 유지.
- 유형별 재사용 원칙 변경은 새 요청부터 적용하며 기존 자료/요청 스냅샷을 소급 변경하지 않는다. 기존 사용자의 선택을 새로운 추천 기본값으로 덮어쓰지 않는다.
- UI 시안과 웹앱→학습지→수정→새 대화 재개의 한 흐름을 먼저 검증한 뒤 데이터 안전장치와 구현 진행. 기존 자료 종류는 제거하지 않고 3종 중심으로 차별화된 동작 먼저 구현.

질문:

2. 이전 검토에서 참고자료 본문과 변경 후 점검 유효성 표시를 후속으로 미뤘던 권고를 최신 목적에 맞게 수정할 필요가 있는가?

4. 여전히 막아야 할 과장/데이터 손실/초보자 마찰 3개 이내.
